# 결정 사항과 배경 (작업 이어가기용 메모)

새 대화나 새 작업자가 이 파일만 읽어도 같은 이해에서 이어갈 수 있도록 남기는 기록입니다.

## 프로젝트 구성
- **강설량 측정 페이지** (`index.html`, `app.js`, `data/*.json`): 기존 페이지. 연도별 신적설과 관측소 지도. 데이터는 HTML이 아니라 `data/` 의 JSON 파일.
- **장비 지원 페이지** (`equipment/`): 제설장비 지원 현황. 최상위 탭("강설량 측정 / 장비 지원")으로 `index.html` 에서 불러옴(iframe).
- 이 저장소는 **공개(public)** 입니다. 장비 지원 쪽은 가상 차량번호·가짜 운전원 샘플만 올립니다. **실제 데이터는 저장소에 넣지 않습니다.**

## 배포와 서버
- 지금 공개 주소는 GitHub Pages(`*.github.io`). main 에 병합하면 1~2분 안에 반영.
- 서버 이전 후보: **Cloudflare**(Pages/Workers + D1 데이터베이스) 를 우선 검토. 이유: 정적 파일 전송량 무제한, 서버 기능 하루 10만 건, DB 내장(하루 읽기 500만 행 / 쓰기 10만 행 / 저장 5GB).
- Vercel 무료(Hobby)는 **개인·비상업 전용**이라 회사 업무에는 부적합. AWS/Azure는 서울(한국) 리전 장점이 있으나 설정이 복잡.
- 확인 필요: Cloudflare 무료 플랜의 상업적 이용 약관.
- 규모: 동시 약 200 아이디. 수정은 하루 사람당 수십 건 수준.

## 저장할 데이터
- 읽기 전용(큰 파일): 연도별 강설량(`data/snow_data.json` 약 7.8MB), 기관별 노선(`data/roads.json`, `data/hierarchy.json`) → 파일로 둠.
- 서버 DB: 운전원 현황, 지사별 요청·편성, 기관별 장비, 로그.

## 동시 사용에 대한 결정
- 같은 장비·운전원을 **두 사람이 동시에 고치는 일은 없음**(확인됨) → 버전 충돌 검사는 필수 아님.
- 그래도 저장은 **바뀐 행만** 보낸다.
- 다른 사람의 수정은 **새로고침할 때만** 보이면 됨(자동 새로고침 없음).

## 예상 적설 연동 (2026-10-05, 사용자 결정)
- 기상청 단기예보 격자 SNO(1시간 신적설) — **예보를 받은 시각으로부터 24시간** 합, 지사 격자 중 가장 큰 값. 지사가 직접 넣던 값은 일단 기상청 값으로 **바꿈**(지사 입력은 나중에 추가할 수 있음).
- 받는 기간·조건은 특보와 같음(기준일자를 만든 시각부터 확정까지). 단기예보 발표가 3시간마다라 그때만(발표 15분 뒤). 확정하면 고정.
- 격자 API 는 지역(타일)으로 나눠 받는 방식이 아니라 요청 1번 = 전국 1시간치 → 24번 요청이 가장 작은 단위.

## 대설 특보 연동 (2026-10-05, 사용자 결정)
- 대설만, 예비특보 포함. 단계 색: 예비 = 노랑, 주의보 = 주황, 경보 = 빨강. 특보 칸은 자동 표시(체크칸 없앰), 지사는 고칠 수 없음.
- 기상청 키는 **Supabase Edge Function 비밀값(`KMA_AUTH_KEY`)으로만** 보관. `wrn_now_data_new` (권한 오류면 `wrn_now_data`).
- (같은 날 수정) 특보는 갱신 주기가 따로 없어 **10분마다(매시 01·11…분)**, 그리고 **기준일자 당일~+2일 중 확정을 기다리는 지사가 있을 때만** 받음 — 무료 한도·DB 용량 절약. 수집 기록은 실패·변화 때만.
- (같은 날 다시 수정) 받는 기간의 시작은 **기준일자를 만든 그 시각**(만들자마자 한 번, 그 뒤 01·11…분). 끝은 모두 확정할 때(늦어도 기준일자 +2일).
- (같은 날) 지사별 요청·편성은 **대설특보만**, 제목 '대설특보 발표' 아래 종류·발표·발효. 다른 특보는 저장해 두고 관리자 창의 종류별 탭에서만 봄. 지난 특보 기록은 대설만.
- (같은 날, 확인용) 특보가 잘 들어오는지 보려고 **모든 종류**를 지사별 요청·편성에 표시. 확인 뒤 대설만으로 되돌림 — git 되돌리기가 아니라 서버 스위치(`settings('warnings')`)로. 화면 코드는 두 경우 모두 처리.
- 확정 순간 특보를 서버가 고정. 못 받은 상태(자료 없음 등)면 **특보 없음으로 고정**. 확정 후 지사 수정 잠금은 필요 없음(지사가 쓰는 칸이 아님). 다시받기 버튼 없음.
- 지사 ↔ 특보구역: 고속도로 구간 × 시·군·구 경계(통계청 2013 공개 경계)로 1차 자동 → 관리자가 화면에서 빼고 더함. 나뉜 시·군(평지/산지 등)은 모두 넣고 시작, 섬 구역은 뺌.

## 위치(좌표) 관련 계획 — 강설량·특보 연동
- 적설은 **24시간 신적설**(최근 24시간 새로 내린 양), 특보는 해당 지역 특보.
- 지사 관할이 여러 지역에 걸치므로 **IC/JC/영업소 좌표**로 확인. 기준 위치는 **표준노드링크**, 도로공사 현황은 **"어느 노드가 어느 기관 소속인지"만** 구분하는 용도.
- 지점 → 특보 구역(시·군, 강원은 평지/산지 구분), 지점 → 적설 칸(기상청 고해상도 격자 500m 또는 관측소) 대응표를 **미리 만들어 두고** 서버가 주기적으로 받아 저장.
- 지사별 표시: 적설은 **가장 큰 값과 그 지점**, 특보는 구역별 종류·등급 목록.
- 노드 표에 저장할 것: 노드 ID, 이름, 유형(IC/JC), 위도·경도, 노선 번호, 소속 기관(경계는 복수 가능), 매칭 방법, 검수 여부. 지도 표출용으로 GeoJSON 내보내기.

## 코드 구조에 대한 결정
- 큰 단위로만 분리: `css/style.css`, `js/sample-data.js`, `js/api.js`, `js/app.js`.
- **화면별 세분화는 UI가 확정된 뒤에** 한다. (UI·데이터가 아직 최종본이 아님)
- 자동 테스트(`tests/test_equipment.py`)와 규칙 문서(`docs/equipment-rules.md`)로 코드를 직접 읽지 않아도 검토할 수 있게 한다.

## 법적·개인정보 메모 (일반 정보, 법률 자문 아님)
- 운전원 이름·전화번호, 사번, 접속 IP 는 모두 개인정보로 다룸.
- 해외 서버 사용 시 **국외 이전 안내**가 동의서/처리방침에 필요할 수 있음.
- 접속기록(아이디, 일시, IP, 조회·수정 내용)은 **1년 이상 보관**, 일반 사용자는 수정·삭제 불가.
- 최소수집 원칙: 꼭 필요한 정보만 저장(이름 대신 일부 가림 표시 등).

## 관할 고속도로 변경 기능 (강설량 페이지)
- 요구: 지사 관할 고속도로를 중간에 바꾸고, 신설 기관을 추가하고, 지사를 다른 본부로 옮길 수 있게 한다. **기존 구분은 그대로 두고 수정만** 가능하게 한다.
- 단위: 링크 전체를 잘게 나누지 않고 **IC/JC 사이 구간**(약 690개)으로 나눠 데이터를 줄였다.
- 끝점이 IC/JC가 아닌 22곳은 **가장 가까운 IC/JC로 보정**하기로 결정(간단히 보는 지도라 정확도 요구가 낮음). 문제가 있으면 이전 커밋으로 되돌린다.
- 변경은 원본을 덮어쓰지 않고 **`data/jurisdiction_changes.json` 에 이벤트로 쌓는다.** 이력과 되돌리기가 쉽다.
- 관할이 바뀌면 **적설 기록도 새 관할로 다시 계산**한다. 과거 시즌 포함, 바뀐 지사만. 관측소 배정 규칙(5km, 5대 이하면 6→7→8km)은 신설·변경 지사에도 그대로 적용.
- 권한: 변경은 **관리자만**. 지금은 서버가 없어 화면 모드만 있고, 실제 반영은 저장소 쓰기 권한이 필요하다. 서버를 붙이면 서버에서 관리자 아이디를 검사한다.
- 신설 노선은 **나중에 표준노드링크로 가져오며**, 그때도 IC/JC 기준으로 나눈다. 이 작업은 Claude에게 파일을 주면 `tools/build_jurisdiction.py` 방식으로 진행한다.
- 전국표준노드링크 원본(노드 약 162MB, 링크 약 327MB)은 저장소에 넣지 않는다. QGIS에서 고속도로 링크(ROAD_RANK=101)와 고속도로에 닿은 노드만 걸러 쓴다.
- 확인 필요: **적설관측지점 전체 목록**(기상청 API허브 stn_snow.php, 약 669곳)의 좌표를 받아 `data/stations.json` 에 반영해야 새로 편입되는 지역의 관측소를 놓치지 않는다.
- **미지정 고속도로**: 어느 지사에도 속하지 않은 고속도로를 `owner = null` 구간으로 `data/sections.json` 에 추가(`tools/add_unassigned_sections.py`, 325구간 약 804km). 눌러서 지사에 배정하거나 지사 구간을 미지정으로 되돌릴 수 있다. `hierarchy.json`, `snow_data.json` 은 바뀌지 않는다.
- **저장 방식 안내**: 관리자 모드에서 항상 보이는 저장 바 + 저장 후 GitHub 업로드 순서 안내. 서버가 없는 동안 실제 반영은 GitHub 에 파일을 올리는 방식이다.
- **민자 본부**: 한국도로공사가 관리하지 않는 고속도로를 구분하기 위해 본부 목록에 `민자`를 추가(`sections.json` 의 `hqs`). **관측소·적설은 계산하지 않고** 강설량 화면 데이터(HIERARCHY, 적설 기록)에도 넣지 않는다. 처음엔 기관을 만들지 않았고, 어떤 도로가 어느 민자 기관인지는 관리자가 화면에서 지정한다.
- **조작 편의**: 지도를 확대할수록 선이 굵어지게(줌별 굵기), 선을 정확히 누르지 않아도 화면 14px 이내 가장 가까운 구간이 눌리게, 목록의 노선명을 눌러도 지도에서 누른 것과 같이 선택되게 했다.

## 서버 구성 재정리 (Cloudflare 구상 v2)
- **Cloudflare는 무료 플랜만** 쓴다. 개인 계정이고, 운전원 이름·전화번호를 저장하지 않으므로(차량번호만) 개인정보가 사실상 없다 → **보안팀 문의는 필수가 아니다**. (회사 방침상 업무 자료를 개인 계정에 올려도 되는지는 사용자가 판단. 남는 것은 접속 아이디·IP뿐이며, 아이디를 기관코드+번호로 만들면 더 줄어든다)
- **workers.dev는 회사에서 안 열린다** → 수집 Worker는 접속하지 않아도 자동으로 도는 쓰기 전용으로 만들고(공개 주소 없음), 읽기는 pages.dev 함수가 한다.
- **적설**: 과거 시즌은 파일. 올해 시즌부터 D1이며, 전날 적설은 **사용자가 기상청 API 콘솔에서 받아 관리자 화면에서 업로드**한다(자동 수집은 제외). 화면은 요약본 한 줄만 읽는다.
- **예보·특보**: Worker가 공공데이터포털 API로 10분 간격 분할 실행(한 번에 약 40격자). 격자는 지도에서 직접 골라 기관에 편입하며, **한 격자를 여러 기관이 공유할 수 있고** 호출은 합집합을 한 번씩만 한다.
- **현재 HTML은 D1과 그대로 호환되지 않는다**: 브라우저가 D1에 직접 접속할 수 없고, github.io는 서버 코드를 못 돌리며, 지금 화면은 큰 JSON 파일을 통째로 받아 계산한다. 서버(pages.dev 함수)가 D1을 **지금과 같은 모양의 JSON**으로 조립해 주면 화면 코드는 거의 그대로 쓸 수 있다.
- 설계 문서: `docs/d1-schema-design.md`, 표 정의 초안: `docs/d1-schema-v1.sql`.

## 첫 화면 로그인 잠금 (2026-10)
- 첫 화면 전체를 로그인 필수로 한다. 로그인 전에는 화면과 자료 파일을 불러오지 않는다.
- 로그인 상태 보관은 **쿠키·캐시가 아니라 브라우저 저장소(localStorage/sessionStorage)** 를 쓴다. 우리 서버가 없는 정적 사이트(GitHub Pages)이기 때문. 자동 로그인 = localStorage(관리자 7일·그 외 30일, 기본 꺼짐), 아니면 sessionStorage. 아이디 저장 = 아이디만 localStorage.
- **이 잠금은 화면을 가리는 것이며 자료 보호가 아니다.** `data/*.json` 은 공개 저장소의 파일이라 직접 받을 수 있다. 실제 보호가 필요한 자료(장비·요청·기록)는 Supabase 에만 두고, 첫 화면의 자료도 "기준정보 이전 → 화면 연결" 뒤에 로그인으로 보호된다.
- 관리 콘솔 비밀번호 일괄 설정 표의 본부·지사 순서는 강설량 측정 화면(`data/hierarchy.json`)과 같다(본부 순서 → 지사 번호 B001…). `tests/test_hierarchy_order.py` 가 실제 자료로 일치를 확인한다.

## 작업 방식 (2026-10)
- 사용자의 요청에 따라 **앞으로는 브랜치·PR·미리보기(시연 화면) 없이 변경을 바로 main 에 반영**한다. (main 에 반영되면 GitHub Pages 에 1~2분 뒤 배포됨)
- 대신 **반영 전에 전체 자동 시험을 모두 통과**시키고, 변경은 작게 나누어 커밋한다. 문제가 생기면 해당 커밋만 되돌린다(`git revert <커밋>`).
- 데이터 삭제, 보안·권한 규칙 변경, 서버(Supabase) 구조 변경처럼 되돌리기 어려운 일은 **실행 전에 먼저 알리고 확인**받는다.
- Supabase(서버)에 이미 적용한 변경은 `supabase/migrations/` 에 SQL 로 기록한다.

## 관할 변경 권한과 구간 변경 요청 (2026-10)
- 기관별 관할 고속도로 탭의 **편집은 관리자 아이디로 로그인했을 때만** 가능하다. "관리자 모드" 체크박스는 없앴다(예보 격자 편입 탭도 같음).
- 지사 계정은 구간을 골라 **[구간 변경 요청]**으로 관리자에게 다른 기관으로 옮겨 달라고 요청한다. 관리자가 로그인하면 알림창이 뜨고, 이동 준비 → 저장 시 승인 처리된다. 요청·승인은 Supabase 표 `jurisdiction_requests`(권한은 DB가 검사).
- 요청은 어느 구간이든 어느 기관으로든 보낼 수 있다(자기 지사 구간만으로 제한하지 않음). 필요하면 나중에 제한한다.
- **예보 격자 편입 탭은 관리자 아이디에서만 보인다**(지사·장비 계정은 격자 자료도 불러오지 않음). 단 `data/*.json` 은 공개 저장소 파일이라 주소를 알면 받을 수 있다.
- 미지정 구간은 점선이 아니라 **회색 실선**으로 표시한다.

## 기준정보 이전 (2026-10)
- 구간·관측소·지사별 관측소·예보 격자 편입의 **기본(baseline) 자료를 Supabase 표로 옮겼다.** 변경은 이력으로 그 위에 쌓는다(파일 방식과 같은 구조). 과거 시즌 적설·배경 도로는 파일로 둔다.
- 옮기는 일은 **서버 안의 함수가 GitHub 공개 파일을 직접 읽어서** 한다(자료가 대화·PC를 거치지 않음). 검사 통과 후 **한 번에 교체**(전부 성공/전부 취소), 변경 이력이 있으면 중단.
- 화면은 아직 파일을 읽는다. 화면 연결 전에 관할·격자 변경 저장이 DB 이력에도 쌓이도록 바꾼다.

## 격자 편입 제외·미지정 구간 가시성 (2026-10)
- 예보 격자 편입 탭의 **[편입 제외]는 기관을 고르지 않는다.** 칸이 속한 기관을 자동으로 찾아 뺀다. 여러 기관이 공유한 칸이 섞여 있을 때만 어느 기관에서 뺄지 확인한다. 변경 이력 형식(`remove` + `from`)은 그대로이고 기관마다 이벤트가 따로 쌓인다.
- 미지정 고속도로는 회색(#8a8a8a)이 너무 연해서 **진한 회색(#3f3f3f) + 흰 테두리 + 1px 굵게**로 바꿨다. 점선은 쓰지 않는다(요청 사항 유지). 명도 대비는 지도 바탕 기준 약 9.7:1(이전 약 3.2:1).

## 변경 저장을 서버로 (2026-10)
- 관할·격자 변경은 **파일을 내려받아 GitHub 에 올리는 방식을 없애고 서버(Supabase)에 바로 저장**한다. 모든 사용자가 같은 이력을 읽고 즉시 반영된다. (기준정보 이전 때 "화면은 아직 파일을 읽는다"고 한 부분 중 **쓰기·이력 읽기**를 먼저 연결함. 기본 자료 읽기는 다음 단계)
- 서버에 연결하지 못하면 이력은 예전 파일로 대신 읽고 **저장을 막는다**(잘못된 화면 위에 덧쓰지 않기 위해). 저장 실패 시 변경 대기는 유지하고 [파일로 받기]를 비상용으로 둔다. 이력 백업 내려받기를 둔다(무료 플랜은 자동 백업 없음).
- 예전 "이 브라우저에만 임시 적용" 기능은 저장이 바로 적용되므로 삭제했다.

## 저장 안내 한 줄·변경 대기 패널 한 곳·새로고침 없는 반영 (2026-10)
- 저장하면 안내는 **"N건 저장되었습니다."** 한 줄(잠깐 보이는 알림)만 나온다. 설명 창은 쓰지 않는다(실패했을 때만 이유 창).
- **변경 대기 목록·사유·[미리보기][모두 취소][저장]은 지도 오른쪽 위 패널 한 곳**에만 둔다. 왼쪽에는 서버 연결 경고와 저장된 이력만 남긴다. 관할·격자 탭이 같은 구성.
- 관할 변경 저장은 **새로고침 없이** 강설량 화면까지 반영한다. 방식: 이벤트를 적용하기 전의 처음 지사 목록(`HIERARCHY_BASE`)에 저장된 이력 전체를 다시 적용하고(`JurisCore.reapply`), 지사별 일별 신적설을 새 관측소 구성으로 전부 다시 계산한 뒤(처음 자료와 531개 시리즈가 정확히 같음을 확인), 통계·관측소 마커·지사 트리를 다시 그린다. 업로드해 둔 저장 안 된 신적설 자료(`SNOW_DATA`)는 그대로 유지된다. "처음부터 적용한 결과 = 나중에 다시 적용한 결과"를 실제 자료로 시험한다(`tests/test_reapply.js`).
- 예보 격자 탭의 "무료 Worker로는 3시간 안에 못 끝냅니다" 판정은 **Cloudflare 계획 기준(40칸/10분)**이라 Supabase 수집에는 맞지 않아 기준을 바꿨다(한 번 100칸·5분 **추정값**, 실제 수집 함수를 만든 뒤 재서 조정). 판정: 시간 한도 3시간·하루 호출 한도 1만 건, 각각 50%·80%를 넘으면 노랑.
- 미지정 구간(진한 회색 실선)은 구간 이음새가 끊겨 보이지 않도록 둥근 끝 모양을 쓴다.

## 신설 기관 번호가 저장 때 사라지던 버그 수정 (2026-10-03)
- **증상**: 신설 기관을 저장하면 서버에 기관 번호(`id`)가 저장되지 않았고, 다시 읽을 때 서버 줄 번호가 기관 번호가 되었다(예: 영암 → "10", 민자 → "11"). 이미 저장된 이동 이력(`to: "11"`)은 그 번호를 가리키고 있다.
- **원인**: `auth/events.js` 가 화면 이벤트를 DB 행으로 바꿀 때 서버 줄 번호와 겹친다고 보고 `id` 를 payload 에서 뺐는데, 신설 기관(`addBranch`)은 `id` 가 자기 기관 번호다.
- **수정**: payload 에 `id` 를 그대로 저장하고, 서버 줄 번호는 `seq` 에 따로 담는다. **이미 저장된 번호 없는 신설 기관은 서버 줄 번호를 기관 번호로 그대로 읽는다**(그래서 기존 이력과 이동이 깨지지 않음). 시험: 저장→새로고침 후 번호·소속 유지, 번호 없는 옛 줄도 계속 적용.
- 이미 저장된 옛 줄(영암·민자)의 번호를 정식 형식(`B060`, `B061`)으로 고치는 데이터 정리는 하지 않았다(필요하면 따로 확인 후 진행).

## 구간 끊김 메우기 (2026-10-03)
- 지도에서 고속도로가 IC/JC 근처에서 끊겨 보이던 것은 **미지정 구간 생성 도구가 IC/JC 를 지나는 본선을 어느 구간에도 넣지 않았기 때문**이다. 지사 구간 686개는 건드리지 않고(지문 시험), 미지정 구간 188개에 실제 도로 경로를 이어 붙였다. 구간 번호는 그대로라 저장된 이력·요청이 유효하다.
- 건드리지 않은 곳(chain 순서만 이어진 쌍, 원본에 이어지는 길이 없는 곳)은 임의의 직선으로 잇지 않고 보고서(`docs/section-gaps-report.md`)에 남겼다.

## Claude Code 도입 (2026-10-03)
- 사용자는 **개인 컴퓨터에서는 Claude Code 데스크톱 앱, 회사 컴퓨터에서는 claude.ai 채팅**을 쓴다. 두 곳은 서로의 대화를 볼 수 없으므로 **저장소가 공유 기억**이다: `CLAUDE.md`(규칙) + `docs/handoff.md`(인계 메모) + 커밋 메시지 + `docs/decisions.md`.

- 모든 시험을 한 번에 돌리는 `tools/run_all_tests.py` 추가(180개 항목, 병렬, 결과는 `.test-logs/`). 반영 전 통과가 규칙.

## 화면 글자 안전 처리·저장 오류 복구·첫 화면 가볍게 (2026-10-04)
- **강설량 화면(`app.js`)도 모든 이름을 안전 처리(`esc`)해서 넣는다.** 지사·본부 이름은 서버의 변경 이력(신설 기관)에서도 오고, 이력은 지울 수 없으므로 화면에서 반드시 글자로만 다룬다. 시험: `t_html_in_branch_name_is_text`(이름에 `<img onerror>` 를 넣어도 실행되지 않음, 고치기 전 코드에서는 실패함을 확인).
- 관할·격자 [저장] 뒤 예상하지 못한 오류가 나도 "저장 중"에 멈추지 않는다. **서버 저장이 이미 끝났으면 변경 대기를 비워서 같은 내용을 두 번 저장하지 않게** 하고 새로고침을 안내한다.
- 엑셀 라이브러리(xlsx, 약 300KB)는 **[엑셀로 내보내기]를 처음 누를 때** 불러온다(로그인 화면이 빨리 뜨게). 회사망에서 `cdnjs.cloudflare.com` 이 막히면 내보내기만 안내 창으로 실패한다.
- 자료 파일은 `cache:'no-cache'`(바뀌었는지만 확인)로 받는다. 최신 반영은 같고 반복 방문 시 받는 양이 준다.
- 시험용 파일 서버는 여러 요청을 동시에 처리한다(`ThreadingTCPServer`). 한 번에 하나씩이면 큰 JSON 을 보내는 동안 스크립트가 밀려 화면 시험이 무작위로 시간 초과됐다.

## 적설 서버 저장·저장+승인 한 번에·이름 검사·CSP·끊긴 구간 원본 대조·백업 (2026-10-04)
- **적설은 서버에 저장한다.** 원자료 `snow_daily`(관측소×날짜), 화면은 요약본 `snapshots('snow')` 한 줄(약 2.3MB)을 로그인한 상태로 읽고 지사별 값(관측소 최댓값)을 관할에 맞춰 계산한다. 예전 파일의 지사별 값 531개 시리즈와 정확히 같음을 시험으로 확인(`tests/test_snow_snapshot.js`). 관측소는 자료가 있는 680곳 전부(좌표 있는 관측소는 260곳이라 `snow_daily` 외래키를 풂). 기상청 결측 표시 -99.9(2,078개)는 넣지 않는다(지도 라벨에 "-99.9cm"로 보이던 문제도 없어짐).
- 새 적설은 **관리 콘솔 → 적설 자료**에 기상청 메모장(txt)을 올려 [검사]→[저장]. 이미 있는 값과 다르면 기본은 그대로 두고, "덮어쓰기"를 켜야 바뀐다. 첫 화면의 "JSON 저장"과 "브라우저에만 임시 반영되는 txt 업로드"는 없앴다(저장소에 파일을 올릴 필요가 없어짐).
- **관할 저장 + 지사 요청 승인은 DB 함수 `save_jurisdiction` 이 한 번에** 한다. 승인하려던 요청이 그사이 취소·반려됐으면 아무것도 저장하지 않고 이유를 알린다.
- **관할 이력 값은 DB 트리거가 검사**한다(이력은 지울 수 없으므로 잘못된 값이 처음부터 못 들어오게). 신설 기관 이름에 HTML 기호 금지, 번호는 `B000` 형식. 이미 저장된 예전 줄(영암 `10`, 민자 `11`)은 그대로 읽는다.
- **첫 화면에 CSP**: 이 사이트·cdnjs(지도·엑셀 라이브러리)·OpenStreetMap(지도 그림)·Supabase 만 허용, HTML 안 스크립트 금지. 외부 라이브러리는 CDN 유지(사용자: 항상 접속 가능). 저장소 안에 넣는 것은 필수 아님.

DB 기본 자료도 같게 반영(마이그레이션 12, `reference_check` 12항목 모두 true).

## 깨우기만·예전 적설 파일 삭제·기록 규칙 (2026-10-04, 두 번째)
- **백업은 하지 않고 서버 깨우기만 한다**(사용자: 백업 파일은 깨우기 목적이었음). `keepalive()`(현재 시각만 돌려줌, 표 접근 없음)를 비로그인도 부를 수 있게 하고, GitHub Actions 가 공개 키로 월·목 호출 → 비밀값 불필요.
- **GitHub·Claude 외 모든 서비스는 무료**(사용자 방침). 무료 GitHub 는 비공개 저장소로 Pages 불가 → 비공개 전환은 사이트를 Cloudflare Pages(무료)로 옮긴 뒤 하기를 권함(`docs/server-keepalive.md`).

## 신설 기관 정상 등록·번호와 순서 분리 (2026-10-04, 사용자 B안 선택)
- **번호(id)는 이름표, 순서가 아니다.** 이력·요청·계정이 번호로 기관을 가리키므로 한 번 정하면 바꾸지 않는다. 새 기관은 다음 빈 번호(B062…).
- **순서는 이력으로**: 신설 시 `after`(○○ 다음/맨 앞/맨 뒤), 나중에 `orderBranch`. 강설량 표·엑셀·지도 목록이 이 순서를 따른다(`JurisCore.sortHierarchy`). 중간에 끼워도 다른 기관 번호·값은 그대로이고, 표는 줄만 늘어난다(행마다 따로 계산, 엑셀은 값만 들어감).
- **정상 등록 루트**: 신설 기관을 저장하면 DB 트리거(`sync_branch_registry`)가 같은 저장 안에서 `branches` 에 등록, 본부 이동도 반영. 같은 이름이면 저장 전체 취소. → 지사 요청(외래키)·계정이 새 기관을 바로 가리킴.
- **영암·민자**: 지울 수 없는 이력은 두고, 읽을 때 10→B060, 11→B061(이력 안의 '11' 이동 2건도). `branches` 에 B060(광주전남)·B061(민자) 등록(마이그레이션 14). A안(새로 만들고 구간 옮기기)은 빈 기관이 남고 이력이 늘어 택하지 않음.
- 서버 시험 `supabase/tests/branch_registry_test.sql` 13/13.

## 본부 탭으로 지사 색 구분 (2026-10-04, 사용자 결정)
- 문제: 지사 색이 "본부 색 + 밝기 4단계"라 같은 본부 지사끼리 거의 같은 색(완전히 같은 색 25쌍, 맞닿은 지사끼리 같은 색도 있었음).
- 결정: 관할·격자 탭 지도 위에 **본부 탭**. **전체** = 본부마다 색 하나(본부 경계 보기), **본부 선택** = 그 본부 지사만 보이고(다른 본부 선은 숨김, 미지정은 보임) 지사마다 12색 팔레트로 서로 다른 색. 같은 본부 지사끼리 최소 색 차이 ΔE 32.7(이전 0).
- 팔레트는 관측소 지도(app.js)와 같고(`JurisCore.BRANCH_PALETTE`) 본부 안 순서대로 → 같은 지사는 두 화면에서 같은 색. 순서를 바꾸면 색도 따라 바뀜. 본부 지사가 12개를 넘으면 색이 반복됨(지금 최대 10).
- 처음 열 때: 관리자·장비 = 전체, 지사 계정 = 자기 본부(다른 탭으로 바꿀 수는 있음).
- 격자 탭: 같은 본부 탭(민자 제외) + 요약의 **지사별 칸 수(많은 순)·지사당 목표 칸 수**(목표 넘는 지사 빨강, 목표대로면 호출 대상 최대 몇 칸) — 쏠림을 한눈에 보는 용도. 격자 탭의 "영역 선택" 도구와 겹치지 않게 탭은 그 아래 줄.
- 기상청 API 확인(공공데이터포털 단기예보 조회서비스): 호출 1번 = 격자 1칸, 개발계정 하루 10,000건(활용사례 등록 시 증가 신청). **1시간 신적설(SNO)은 단기예보에만 있고 초단기예보에는 없음**(초단기는 강수량 RN1·강수형태 PTY). 특보는 별도 서비스(특보구역 단위)라 격자 수와 무관.

## 세부 권한(2단계)·산하기관 아이디·장비 지원 서버 저장 (2026-10-04, 사용자 결정)
- **권한 = 역할 + 계정마다 켜고 끄는 권한(perms).** 역할은 admin / branch(지사) / equip(지원장비, 출발 기관에 묶임) / hq(지역본부, 본부에 묶임) / viewer. 권한 목록은 표 `permissions`(11개), 서버 규칙은 `private.has_perm('권한')`으로 검사. 관리자는 모든 권한. 화면(첫 화면·관리 콘솔·장비 지원)도 같은 권한으로 탭·버튼을 보임.
- **관리자 계정은 새로 만들지 않는다**(사용자: 필요하면 따로 요청). 계정 함수 `account-admin` 의 create 는 branch·equip·hq·viewer 만, 새 동작 `update`(이름·권한·순서).
- **산하기관 아이디**(관리 콘솔 → 산하기관 아이디 관리 → 새 아이디 만들기 → 추천 13개): 지원장비 4개 = 지역 이름(4글자면 앞 2글자) 로마자 + `gigyae`, 앞에 `ex`(사용자 예시 `exseoulgigyae` 그대로; 표준 로마자는 gigye) — exseoulgigyae·exchungbukgigyae·exjeonbukgigyae·exdaegugigyae. 지역본부 9개 = 지역 이름 전체 로마자 + `ex` — exsudogwon·exseoulgyeonggi·exgangwon·exchungbuk·exdaejeonchungnam·exjeonbuk·exgwangjujeonnam·exdaegugyeongbuk·exbusangyeongnam. 비밀번호는 무작위 임시값으로 만들고 사용자가 "비밀번호 일괄 설정"에서 정함. **계정 생성은 사용자가 버튼을 눌러서**(Claude 가 직접 만들지 않음).
- **장비 경로는 (날짜, 장비)마다 한 줄**(`vehicle_routes`). 예전 화면은 장비마다 "지원일 목록" 하나를 덮어써서 다른 날짜로 보내면 지난 기록이 사라졌다(사용자 질문에 "맞다"). 이제 [확정]한 날짜의 줄만 바꾸고 다른 날짜 줄은 그대로 → 언제든 장비별 날짜 기록을 볼 수 있음. 고치거나 지우면 이전 값은 수정 기록(audit_log)에 남음.
- **[확정] 버튼으로만 저장**(중간 입력이 마구 저장되지 않게, 사용자 제안). 저장은 DB 함수 `save_fleet`·`save_requests` 가 부른 사람 권한으로 한 번에 처리(하나라도 권한이 없으면 전체 취소). 같은 경로를 다시 확정하면 아무 변화·기록 없음.
- **기준일자**(`support_rounds`, 하루에 하나) = 지원 회차. 지사별 요청·편성은 기준일자마다 따로, **확정**(`round_requests.confirmed`)한 지사만 기관별 장비의 피지원 지사 선택지에 나옴. 기관별 장비에서도 기준일자를 고를 수 있고, 고르면 지원일 1이 그 날짜로.
- 지원일 1은 장비마다가 아니라 **표 제목에서 한 번**(관리자·equip.edit.all). 지원 여부에 **정비중**(M) 추가(지원 불가와 같게 취급).
- 이동 현황: 본부 → 지사 계층(그날 지원받는 지사만), 아래 장비 현황도 계층 순서.
- (2026-10-04 이어서, 사용자 결정) **차량번호 → 도공번호**(예: 서울경기-901, DB 열 이름은 plate 그대로, 예전 형식은 서버만 당분간 허용). **지원장비 계정은 장비 추가(자기 기관)·도공번호·지원 여부만**, 날짜별 경로·삭제·지원일 1·초기화는 관리자(마이그레이션 19, 경로 정책·`save_fleet` 도 관리자만). 지사별 요청·편성의 확정은 체크칸 대신 **[확정] 버튼**(누르면 그 줄 바로 저장). **기준일자 삭제** 버튼(요청 함께 삭제, 경로는 남음). 화면은 기준일자 줄을 맨 위에, 나머지 버튼·선택칸은 표 바로 위 도구 줄로 정리, 넓은 화면은 1680px까지 넓게.
- (이어서, 사용자 결정) 도공번호는 `기관 이름 + 숫자`(서울경기901, 입력은 숫자만, DB가 기관 이름 일치 검사). 경로 칸마다 **최초 지원/수정본**(`vehicle_routes.revised`, 수정본이면 모든 지사 선택)과 지사별 **도착 예상 시각**(`times`, HH:M0) — 이동 현황 장비 상세는 도착 요청 대신 도착 예상. 지사별 요청·편성은 보유·최종 열 삭제, [일괄 확정]. (마이그레이션 20)
- (이어서) 최초 지원/수정본은 칸마다가 아니라 **표 위 한 곳**(한 번에 적용). 도착 예상 시각은 **직접 입력**(아무 분), **지원장비도 시각 수정**(지사·구분은 관리자, 트리거 `aa_vehicle_routes_guard`·`save_fleet` 검사, 마이그레이션 21). 이동 현황: 지원기관 이름, 이동정비차 숨김, 제설차/제설기 칸 표, 카드 큰 시각 = 도착 예상·도착 요청은 표지.
- 검토 의견(사용자에게 드린 것): ① 확정 전 화면 값과 서버 값이 다를 수 있으니 확정 바를 항상 보이게 함 ② 두 사람이 같은 칸을 동시에 확정하면 나중 것이 남음(기록에 둘 다 남음) — 필요하면 나중에 "그사이 바뀜" 확인 추가 ③ 장비 삭제는 경로 기록까지 지우므로 평소엔 지원 불가·정비중 사용 ④ Supabase 무료는 읽기 횟수 제한 없음(egress 월 5GB만).
