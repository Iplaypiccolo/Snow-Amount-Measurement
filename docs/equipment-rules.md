# 장비 지원 페이지 — 동작 규칙 (사람이 읽는 문서)

코드를 읽지 않고도 "화면이 이렇게 동작해야 한다"를 확인하기 위한 문서입니다.
코드와 이 문서가 다르면 둘 중 하나가 틀린 것이니, 알려 주세요.
(자동 테스트 `tests/test_equipment.py` 가 아래 내용 대부분을 확인합니다.)

## 1. 아이디 역할과 권한

| | 이동 현황 | 기관별 장비 | 지사별 요청·편성 | 로그 기록 |
|---|---|---|---|---|
| **관리자** (2개) | 보기 | 수정(차량번호·지원 여부·**지원일 1 날짜**·날별 기관) | **모든 지사** 수정 | 보기 |
| **피지원지사** | 보기 | 보기 | **본인 지사 행만** 수정 | 탭 없음 |
| **지원장비** | 보기 | 수정(차량번호·지원 여부·날별 기관. 지원일 1 날짜는 못 고름) | 보기 | 탭 없음 |

- 수정 권한이 없는 칸은 입력창이 아니라 글자로만 보입니다.
- ⚠ 이 권한 검사는 화면 정리용입니다. **서버를 붙이면 서버에서도 똑같이 막아야 합니다.**

## 2. 저장 규칙 (기관별 장비 / 지사별 요청·편성)
- 값을 고치면 "저장하지 않은 변경이 있습니다"가 뜨고, **[저장]을 눌러야 확정**됩니다.
- **[되돌리기]**: 마지막으로 저장한 상태로 돌아갑니다.
- 저장하지 않고 페이지를 닫으려 하거나 다른 아이디로 바꾸면 경고합니다. (아이디를 바꾸면 저장 안 한 변경은 버려집니다)
- 저장 바는 **그 탭을 수정할 수 있는 아이디에게만** 보입니다.

## 3. 입력 확인 규칙
- 차량번호: 형식 `12가3456`(숫자 2~3자리 + 한글 1자 + 숫자 4자리), 다른 장비와 같은 번호는 안 됨. 장비는 바뀌지 않는 고유 번호(V001…)로 관리하므로 번호를 고쳐도 일정·기록은 그대로.
- 지원 일자: **지원일 1 날짜만 관리자가 고르고**, 지원일 2부터는 하루씩 자동으로 이어짐(지원일 1을 바꾸면 나머지 날짜도 함께 밀림, 기관은 그대로).
- 지원 일자별 기관: 지원일 1이 정해져야 기관을 고를 수 있음. 하루에 여러 기관은 ＋로 추가, "지우기"로 삭제. 끝쪽의 기관 없는 날은 저절로 정리됨. 같은 기관을 한 날에 두 번 넣으면 한 번으로 합쳐짐.
- 지원 여부를 "지원"이 아닌 값으로 바꾸면 그 장비의 지원 일자·기관은 모두 비워짐.
- 지원일 칸 수: 2~10개 모두 고를 수 있음. 기관이 들어 있는 날보다 줄이면 확인 후 그 뒤 기관을 지움(저장 전에는 [되돌리기]로 복구).
- 표는 스크롤해도 제목 줄이 맨 위에 고정됨.

## 4. 이동 현황 보는 규칙
- 날짜는 **오늘**로 시작. 위쪽 날짜(‹ ›)에 **실제로 이동하는 장비**만 보임. 그날 이동도 도착 요청도 없는 지사는 숨김.
- 총괄표: **세로 = 피지원 기관**(많아져도 아래로 늘어남, 제목·합계 줄 고정), **가로 = 출발 기관 5곳**(서울경기·충북·전북·대구경북·**지역본부**). 지역본부는 나중에 '지역본부' 탭(지사별 지원 가능 장비)에서 자료를 끌어올 자리이며 지금은 0.
- 기관별 장비의 지원일이 그대로 반영됨: 고른 날짜가 어떤 장비의 지원일 k 이면 그 장비가 그날 들르는 기관 행에 세어지고, 장비 줄에 "k일차 / n일" 표시.
- 아래 필터는 왼쪽 = 출발 기관, 오른쪽 = 장비 종류(세로 구분선). 차량번호 검색칸은 없앰.
- 한 장비가 하루에 여러 기관을 들르면 **각 기관 카드에 모두** 나오고 "N곳 경유" 표시. 총괄표의 합계는 장비를 **1대로** 셈(중복 제외).

## 5. 개인정보 규칙 (운전원 정보는 다루지 않음)
- 이 페이지에는 **차량번호만** 들어갑니다. **운전원 이름·전화번호는 저장하지도, 보여주지도 않습니다.** (운전원 현황 탭, 장비 표의 운전원 열, 연락처 '보기'와 조회 로그는 모두 없앴습니다)
- 그래도 **접속 아이디와 접속 로그(IP)**는 남습니다. 아이디를 사람 이름 대신 **기관 코드+번호**처럼 만들면 개인정보 부담이 더 줄어듭니다.
- 화면에 글자를 넣을 때는 항상 안전 처리(`esc`)를 거침 → 사유 같은 입력칸에 `<script>` 같은 글자를 넣어도 실행되지 않고 글자로만 보임.

## 6. 수정기록 말풍선 (관리자만)
- 값에 마우스를 올리면(모바일은 누르면) **오늘** 수정된 기록이 **최대 3건**(최신순) 보임. 점선 밑줄이 있는 값이 대상.
- 이전 날짜의 기록은 말풍선에 안 보이고 **로그 기록 탭**에서 확인.

## 7. 로그 기록 탭 (관리자만)
- 기록 종류: **접속 · 수정**. 일시 / 아이디 / 구분 / 탭 / 대상 / 내용 / IP.
- 구분·아이디·"오늘만"으로 거를 수 있음. 화면에서 고치거나 지울 수 없음.
- 수정 로그는 **[저장]을 누른 시점**에 남음(같은 칸을 여러 번 고쳐도 "처음 값 → 마지막 값" 한 건).
- ⚠ 지금 화면에서 새로 생기는 기록의 **IP는 "-"**. 서버가 있어야 IP를 알 수 있음.

## 8. 서버로 옮길 때 반드시 지킬 것
1. 권한 검사는 **서버에서 다시** 한다.
2. 저장은 **바뀐 행만** 보낸다. (표 전체를 보내면 다른 사람이 고친 값이 옛 값으로 돌아갈 수 있음)
3. 로그(아이디·시각·IP)는 **서버가 직접 기록**하고, 수정·삭제 불가(추가만 가능). **1년 이상 보관**.
4. 최신 데이터는 **사용자가 새로고침할 때만** 불러온다. (자동 새로고침 없음)
5. 아이디·접속 로그(IP)를 저장하는 서버(Cloudflare 등)의 위치와 보관 기간을 확인한다. (개인정보 범위가 아이디·IP 뿐이라 부담은 작지만 회사 방침을 확인)

## 9. 아직 정하지 않은 것
- 지원장비 아이디를 **기관별로 나눌지**(지금은 하나가 4개 기관 장비를 모두 수정)
- 눈이 올 때마다 지원 계획을 따로 남기는 **"지원 회차"(날짜·건) 개념**을 넣을지(지금은 지사별 요청이 한 줄뿐이라 지난 기록이 쌓이지 않음)
- 장비별로 **기관마다 도착 시각**까지 적을지(지금은 지사별 "도착 요청" 시각을 그대로 보여줌)
- 이동 현황에 **"모든 날짜" 보기**가 필요한지
- 실제 데이터를 **직접 입력할지 / 외부 API에서 가져올지**

## 10. 화면 모드·데모 아이디
- 오른쪽 위 **[라이트 모드] [다크 모드]** 두 칸 버튼(고른 쪽이 진하게). 이 브라우저에 기억.
- "접속 아이디(데모)" 선택창은 정식 출시 전까지 유지(사용자 결정 2026-10-04).
