# 기관별 관할 고속도로 — 동작 규칙 (사람이 읽는 문서)

강설량 측정 페이지의 **"기관별 관할 고속도로"** 탭이 어떻게 동작해야 하는지 정리한 문서입니다.
(자동 테스트: `tests/test_jurisdiction_core.js`, `tests/test_jurisdiction_ui.py`)

## 1. 한눈에 보기
- 지사 관할 고속도로를 **IC/JC 사이 구간**(전국 약 690개) 단위로 나눠서, 지도에서 구간을 눌러 **다른 지사로 옮길 수 있습니다.**
- **신설 기관 추가**, **지사를 다른 본부로 이동**도 같은 탭에서 합니다.
- 바꾸면 영향받는 지사만 **관측소 배정과 일별 신적설이 새 관할로 다시 계산**됩니다. (과거 시즌 포함)
- 기존 구분은 그대로 두고 **변경 내용만 별도 파일에 쌓습니다.** 되돌리려면 그 파일을 이전 커밋으로 되돌리면 됩니다.

## 2. 파일
| 파일 | 내용 | 누가 바꾸나 |
|---|---|---|
| `data/sections.json` | 구간(IC/JC 사이)의 모양과 **기본 소속** | 도구(`tools/build_jurisdiction.py`)가 생성 |
| 서버(Supabase) 표 `jurisdiction_events` | **저장된 변경 이력** (이동·신설·본부 이동). [저장]하면 여기에 한 줄씩 쌓이고 모든 사용자가 같은 이력을 읽음 | 관리자(화면의 [저장]) |
| `data/stations.json` | 관측소 좌표 목록 (배정 계산용) | 도구가 생성. 전체 목록을 받으면 교체 |
| `data/hierarchy.json`, `data/snow_data.json` | 기존 지사·관측소·신적설 데이터 | 기존 방식 |
| `jurisdiction/core.js`, `ui.js`, `style.css` | 계산 / 화면 / 디자인 | 개발 |

## 3. 화면 사용법
1. 탭을 열면 지도에 구간이 **본부별 색**으로 보입니다.
1-2. **선 굵기**: 지도를 **확대할수록 선이 굵어집니다.** (전국 보기 4px → 확대 13단계 11px → 15단계 14px → 최대 16px) 배경 지도의 도로도 확대하면 넓어지므로 선도 함께 굵어져 항상 또렷합니다. 점선 무늬와 선택 테두리도 굵기에 맞춰 커집니다.
2. **구간을 누르면** 그 구간에 **이중 테두리**가 생기고, **시점·종점 IC/JC 이름표**와 소속·길이 팝업이 나옵니다. (팝업을 닫으면 해제)
   - 테두리 색은 구간 색의 밝기에 맞춰 자동으로 정해집니다. 구간 색이 밝으면 **어두운 테두리**, 어두우면 **흰 테두리**를 쓰고, 그 바깥에 반대색 띠를 한 겹 더 둬서 지도 배경 위에서도 떨어져 보입니다. (선과 테두리의 밝기 대비 3:1 이상을 자동 테스트로 확인)
   - **누르기 쉽게 보정**: 선을 정확히 누르지 않아도 **화면에서 약 14px 이내**로 가까운 구간이 눌립니다. 여러 구간이 가까우면 **가장 가까운 구간**이 선택되고, 눌릴 만큼 가까우면 마우스 커서가 손 모양으로 바뀝니다.
3. 왼쪽 목록에서 **지사를 누르면** 그 지사만 강조되고 구간 목록이 펼쳐집니다. 펼쳐진 **노선명(구간 행)을 누르면** 지도에서 그 구간을 누른 것과 똑같이 동작합니다. (관리자·지사 계정: 선택/해제, Shift+클릭 범위 선택 / 장비 지원 계정(보기 전용): 테두리와 팝업) 이미 화면에 보이는 구간이면 지도를 움직이지 않습니다. 맨 위 **"미지정 고속도로"** 행은 어느 지사에도 속하지 않은 고속도로입니다. (아래 4번 참고)
4. **지도에서 바로 수정하기** (**관리자 아이디로 로그인했을 때만**. "관리자 모드" 체크박스는 없고, 로그인한 역할로 정해집니다)
   - 구간을 누르면 선택/해제, **Shift+클릭**은 같은 노선 줄에서 범위 선택, 목록의 체크박스로도 선택합니다. 선택한 구간은 이중 테두리로 표시됩니다.
   - **도착 지사 정하기**: 아래 바의 목록에서 고르거나, **[지도에서 도착 지사 고르기]**를 누르고 **도착 지사의 구간을 지도에서 클릭**합니다. (Esc로 취소. 이미 같은 지사의 구간을 누르면 안내만 나옵니다)
   - 정해지면 "변경 대기"에 쌓이고 지도에서 **점선**으로 표시됩니다. 신설 기관처럼 구간이 아직 없는 지사는 목록에서 고릅니다.
   - **[+ 신설 기관]**: 이름과 소속 본부를 정해 만들고, 구간을 옮겨 채웁니다. 지사를 열면 **본부 변경**도 할 수 있습니다.
   - **저장 바**: 관리자 아이디로 로그인하면 지도 오른쪽 위에 **[미리보기] [모두 취소] [저장]** 바가 항상 보입니다. 변경이 없으면 버튼이 흐리게 꺼져 있고, 변경이 생기면 "● 저장하지 않은 변경 N건"으로 바뀌며 [저장]이 켜집니다.
   - **[저장]**을 누르면 변경이 **서버(Supabase)에 바로 저장**되고 **모든 사용자에게 즉시 적용**됩니다. **GitHub 에 파일을 올릴 필요가 없습니다.** 저장이 끝나면 "저장했습니다" 창이 뜨고, 이 탭의 지도·목록은 이미 새 관할로 바뀝니다. 다른 탭(연도별 신적설·관측소 지도)의 적설 계산까지 새 관할로 바꾸려면 창의 **[새로고침해서 모두 반영]**을 누릅니다.
5. 왼쪽 아래 **변경 대기**에서 개별 변경을 취소(×)하거나 **모두 취소**할 수 있습니다. (신설 기관을 취소하면 그 기관으로의 이동도 함께 정리)
6. **[미리보기]**: 바뀌는 지사의 관할 길이, 관측소 추가·제외, 최신/전체 시즌 최대 신적설의 전·후를 보여줍니다.
7. **[변경 저장]**: 변경 사유를 적을 수 있고, 서버에 저장되면 변경 대기가 비고 "저장된 변경 이력"에 쌓입니다. 저장 중에는 버튼이 꺼집니다.
8. **저장하지 못했을 때**(인터넷·서버 문제): "저장하지 못했습니다" 창에 이유가 나오고 **변경 대기는 그대로 남습니다.** [다시 저장]을 누르거나, 급하면 **[파일로 받기]**로 변경 내용을 보관할 수 있습니다. 서버에서 변경 이력을 **읽지 못한** 상태(예전 파일 기준으로 보고 있음)에서는 잘못된 화면 위에 덧쓰지 않도록 [저장]이 꺼지고 경고가 나오며, 새로고침해 서버에 연결되면 정상으로 돌아옵니다.
9. **[이력 파일로 내려받기(백업)]**(관리자, 저장된 변경 이력 안): 이력 전체를 예전 파일 형식으로 내려받아 보관합니다. (무료 플랜은 자동 백업이 없으므로 가끔 받아 두면 좋습니다) 예전의 "이 브라우저에만 임시 적용" 기능은 저장이 바로 적용되므로 없앴습니다.

## 3-0. 구간 변경 요청 (지사 → 관리자)
관리자도 틀린 구간이 있을 수 있어서, 지사가 관리자에게 "이 구간을 다른 기관으로 옮겨 달라"고 요청할 수 있습니다. (자동 시험: `tests/test_jurisdiction_requests.py`, 서버 규칙: `supabase/tests/requests_test.sql`)

**지사 계정**
1. 지도에서 구간을 누르거나(Shift+클릭: 범위), 왼쪽 목록의 노선명을 눌러 선택합니다. 지사를 열고 [이 지사 구간 전체 선택]도 됩니다.
2. 아래 바의 **[구간 변경 요청]** → 옮길 기관(비워 두면 "관리자가 정해 주세요")과 사유(선택, 200자 이내)를 적고 **[요청 보내기]**.
3. 왼쪽 **"내 변경 요청"**에서 상태(대기 중 / 승인 / 반려 + 관리자 의견)를 봅니다. 대기 중인 요청은 [지도에서 보기], [요청 취소]가 됩니다.
4. 한 번에 구간 **60개**까지, 처리 대기 요청은 지사당 **20건**까지입니다. 장비 지원 계정은 요청할 수 없습니다.

**관리자 계정**
1. 로그인하면 **"관할 노선 변경 요청이 있습니다 — ○○ 지사 요청 N건(구간 M개)"** 알림창이 뜹니다. [확인하러 가기]는 관할 탭의 요청 목록으로 갑니다. 같은 로그인에서 이미 본 요청은 알림창이 다시 뜨지 않고, 새 요청이 오면(1분마다 확인) 다시 뜹니다. 관할 탭 이름 옆에 대기 개수가 표시됩니다.
2. 요청 카드: **[지도에서 보기]**(요청한 구간을 지도에 표시), **[이동 준비]**(요청대로 "변경 대기"에 추가. 도착 지사가 비어 있으면 고르는 창이 뜸), **[반려]**(사유 입력).
3. 변경 대기에서 **[저장]**을 누르면 서버에 저장되고, 그 이동에 연결된 요청이 **승인 처리**됩니다. (이동 준비만 하고 저장하지 않으면 승인되지 않습니다) 이미 요청한 지사 소속이면 확인 후 바로 승인(완료) 처리합니다.
4. 저장된 이동 이력에는 `req`(요청 번호)가 함께 기록되어 나중에 어느 요청으로 바뀌었는지 알 수 있습니다.

**서버가 지키는 규칙**: 요청한 지사·작성자·상태는 DB가 정하고(속일 수 없음), 지사는 자기 지사 요청만 읽고 자기 대기 요청만 취소할 수 있으며, 승인·반려는 관리자만, 요청 기록은 아무도 지울 수 없고, 모든 변경은 접속·수정 기록에 남습니다.

## 3-1. 민자 본부
- 본부 목록 맨 아래에 **"민자"**가 있습니다. 한국도로공사가 관리하지 않는 민자 고속도로를 **구분만** 해 두는 곳입니다. (보라색 계열로 표시)
- **관측소 배정과 적설 계산을 하지 않습니다.** 민자 기관에 구간을 옮겨도 강설량 측정 화면(연도별 신적설, 관측소 지도)에는 나타나지 않고, 지사 수 통계에도 들어가지 않습니다.
- 사용법: **[+ 신설 기관]**에서 소속 본부를 "민자"로 골라 기관(예: 운영 회사)을 만들고, 미지정 구간이나 다른 지사의 구간을 그 기관으로 옮깁니다. 지사를 **본부 변경**으로 민자로 옮길 수도 있고, 다시 일반 본부로 옮기면 그때 관측소·적설이 새로 계산됩니다.
- 지사 구간을 민자로 넘기면 **넘긴 지사의 관측소·적설은 다시 계산**됩니다. 미리보기에는 민자 쪽에 "관측소·적설 계산 안 함"으로 표시됩니다.
- 처음에는 민자 기관이 하나도 없습니다. 미지정 구간 중 민자 고속도로(예: 인천공항, 서울문산, 용인서울 등)를 민자 기관으로 옮겨 분류하세요.

## 3-2. 미지정 고속도로 (어느 지사에도 속하지 않은 고속도로)
- 지도에서 **진한 회색 실선**(점선이 아님)으로 보이고, 밝은 지도 위에서도 잘 보이도록 **흰 테두리를 깔고 소속 구간보다 1px 굵게** 그립니다(확대하면 함께 굵어지고, 다른 지사를 강조하면 함께 흐려짐). 그리고 누르면 "소속: 미지정"으로 나옵니다. 지사 구간과 똑같이 **선택해서 지사에 배정**할 수 있습니다. 반대로 지사 구간을 **[미지정으로 되돌리기]**로 소속을 없앨 수도 있습니다.
- 목록 맨 위의 **"미지정 고속도로"** 행을 누르면 미지정 구간만 강조되고, 관리자·지사 계정에는 [미지정 구간 전체 선택]이 나옵니다.
- 미지정 구간을 지사에 배정하면 그 지사의 관측소 배정과 일별 신적설이 새로 계산됩니다. (미지정 쪽은 계산할 것이 없습니다)
- 만든 방법: `tools/add_unassigned_sections.py` 가 표준노드링크에서 **현재 지사 구간과 겹치지 않는 고속도로 본선**을 찾아 IC/JC 사이 구간으로 만들었습니다(상·하행 중 한쪽). **325개 구간, 약 804km**이며 상세는 `docs/unassigned-sections-report.md` 입니다.
- ⚠ **한계**: IC/JC 로 이어지지 않는 일부 도로는 구간으로 만들어지지 않아 지도에 연한 회색 배경선으로만 보이고 선택할 수 없습니다. 이런 도로를 넣으려면 해당 구간의 표준노드링크를 다시 확인해야 합니다. 이미 지사에 배정된 노선의 반대 방향 차로가 미지정으로 잘못 잡혔을 가능성도 있습니다.

## 4. 반영(저장) 방법
- 서버에 저장하므로 별도 반영 절차가 없습니다. 되돌리려면 관리자가 반대 방향으로 다시 이동합니다(이력은 지우지 않고 쌓습니다).
- **되돌리기**: 그 파일을 이전 커밋 내용으로 되돌립니다.
- ⚠ **권한**: 화면의 편집 도구는 **관리자 아이디로 로그인했을 때만** 보입니다. 다만 화면 제한은 편의 기능이고, **실제로 반영할 수 있는 사람은 저장소에 쓸 수 있는 사람뿐**입니다. 지사 계정의 변경 요청 권한은 서버(DB)가 검사합니다.

## 5. 변경 파일 형식 (`events` 배열에 순서대로 쌓임)
```
{ "t":"move",      "sections":["S0001","S0002"], "to":"B012" }     구간 이동 (to = 도착 지사 번호)
{ "t":"addBranch", "id":"B060", "hq":"강원", "name":"신설지사" }    신설 기관
{ "t":"moveHq",    "branch":"B012", "hq":"충북" }                   지사의 본부 이동
```
각 이벤트에는 `at`(시각), `note`(사유), 화면 표시용 `from`·`km` 등이 함께 저장됩니다.
- 없는 지사·없는 본부·중복 이름 등 **올바르지 않은 이벤트는 무시**됩니다.
- 지사 번호(`B001`…)는 이름이 아니라 번호로 연결되어 있어, 본부를 옮겨도 연결이 끊기지 않습니다.

## 6. 적설 재계산 규칙
- **관측소 배정**(지금 사이트의 규칙 그대로): 지사 관할 선에서 **반경 5km** 이내 관측소가 **5대 초과**면 확정, **5대 이하**면 6km → 7km → 8km로 넓힙니다(8km에서 멈춤). 거리는 관할 선(점-선분)까지의 최단거리입니다. 한 관측소가 여러 지사에 중복으로 속할 수 있습니다.
- **일별 신적설**: 지사의 하루 값 = 배정된 관측소들의 **그날 최댓값**. 바뀐 지사만 전 시즌을 다시 계산하고, 나머지는 그대로입니다.
- 관할 구간이 0개인 지사는 관측소 0곳, 적설 값 없음으로 표시됩니다.
- 검증: 이 규칙으로 현재 59개 지사의 관측소와 반경을 다시 계산하면 **전부 그대로 재현**됩니다(자동 테스트).
- ⚠ **한계**: `data/stations.json` 에는 지금 **지사에 배정된 적이 있는 관측소 260곳**의 좌표만 있습니다. 새로 편입되는 지역에 다른 관측소가 있어도 빠질 수 있으니, **기상청 적설관측지점 전체 목록(좌표 포함)을 받아 교체**하면 정확해집니다. 미리보기에 이 경고가 표시됩니다.

## 7. 구간(IC/JC 사이)을 만든 방법 — `tools/build_jurisdiction.py`
- 입력: 전국표준노드링크에서 QGIS로 걸러낸 **고속도로 링크(ROAD_RANK=101)** 와 **고속도로에 닿은 노드** 파일, 노드 파일의 `.prj`.
- 기존 지사 관할 구간(`routeSegments`)을 **그대로 읽어** IC/JC 노드 위치에서 잘라 구간을 만들었습니다. (이름에 IC·JC·분기점·나들목이 들어간 노드를 IC/JC로 판별. 같은 IC의 여러 연결로 노드는 하나로 묶고 300m 미만 구간은 이웃과 합침)
- **끝점 보정**: 관할 구간의 양 끝점 중 IC/JC가 아닌 22곳을 도로를 따라 가장 가까운 IC/JC로 옮겼습니다(줄이거나 늘림, 최대 4.5km, 합계 약 23km). 늘린 부분이 다른 지사 구간과 겹치면 보정하지 않도록 되어 있습니다. 결과는 `docs/jurisdiction-build-report.md`.
- 보정으로 구간이 바뀐 **13개 지사**만 `hierarchy.json` 이 바뀌었습니다(나머지 46개 지사는 한 글자도 바뀌지 않음). 관측소 구성은 모두 그대로였고, 청송 지사의 반경 표시만 5km → 6km로 바뀌었습니다.
- **신설 노선을 가져올 때**: 같은 방식으로 새 링크·노드 파일을 걸러서 올리면, IC/JC 기준으로 나눈 구간을 `sections.json` 에 추가(소속은 비워 두고 신설 기관에 배정)하는 작업을 합니다.

## 8. 아직 정하지 않은 것
- 서버 연결 후 **관리자 아이디(2개) 검사**를 서버에서 어떻게 할지
- 신설 노선을 넣는 구체적 절차(파일 형식, 미분류 구간을 화면에서 어떻게 보여줄지)
- 지사별 반경을 **수동으로 고정**하는 기능이 필요한지 (지금은 규칙으로만 계산)
