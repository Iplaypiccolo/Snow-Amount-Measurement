# 관할 노선과 예보 격자 자동 연동 — 적용 전 검토

## 원인과 수정 범위

관할 화면은 `jurisdiction_events`를 기본 노선에 적용하지만 격자 화면과 서버의 `private.grid_effective()`는 최초 `grid_assign`만 사용했다. 따라서 관할을 옮겨도 자동 격자 소속은 예전 상태였고, 영암·합천도 격자가 없었다. `sections.owner_id`는 원본 소속이며 현재 관할 그 자체가 아니다.

기존 1km 샘플링 기준으로 1,025개 구간과 격자 2,352개 관계를 생성한다. 화면과 서버 모두 **구간별 격자 × 최신 관할 소속**으로 자동 편입을 계산한 뒤, 저장된 수동 편입·제외 이력을 적용한다. 여러 구간이나 기관이 공유하는 칸은 중복 없이 계산한다. 미지정이나 민자로 옮기면 자동 편입에서 빠진다. 과거 이력과 원본 노선은 수정하지 않는다.

## 실제 자료로 계산한 결과

| 대상 | 현재 | 노선 연동 수정 후 |
|---|---:|---:|
| 영암 | 0칸 | 17칸 |
| 합천 | 0칸 | 20칸 |
| 전국 고유 격자 | 924칸 | 962칸 (+38) |
| 지사별 편입 관계 합계 | 1,059개 | 1,111개 (+52) |

영암은 9구간(기존 2 + 신설 7), 합천은 신설 6구간을 반영했다. 신설 노선의 일부 좌표는 원본에 ‘대략 위치’로 표시돼 있으므로 결과도 그 자료 기준이다. 모든 지사별 수량은 `74_branch_grid_counts.csv`에 기록했다. 운영 서버에서는 쓰기 없이 SELECT로 검증해 같은 수량을 얻었다.

수동 추가·제외는 기관에 직접 지정한 예외로 유지된다. 과거 수동으로 추가한 칸은 노선이 이동해도 기존 기관에 남을 수 있고, 새 기관의 자동 편입과 공유될 수도 있다. 이번 작업에서 수동 예외를 임의로 없애지 않는다.

## 적용할 SQL

전체 실행문: **`74_route_grid_review.sql`**. 아직 운영 서버에 적용하지 않았다.

1. 검토한 노선 좌표 지문과 실제 서버가 일치하는지 검사한다. 다르면 중단한다.
2. 비공개 `private.section_grid`에 구간별 격자 관계만 저장한다. 로그인 사용자와 공개 API에는 이 표를 직접 공개하지 않는다.
3. `private.section_owners()`는 마지막 유효 관할 이동을 읽는다. 예전 10/11 기관 번호도 B060/B061로 해석한다. `NONE`은 실제 미지정으로 처리한다.
4. 기존 내부 함수 `private.grid_effective()`가 현재 관할 자동 편입 위에 수동 이력을 적용하도록 바꾼다. 새 공개 RPC나 새 계정 권한은 추가하지 않는다.

기존 `jurisdiction_events`, `grid_events`, `grid_assign`, `sections`, 확정 자료를 고치거나 지우는 SQL은 없다. 4km 확대도 포함하지 않았다. 내부 표는 RLS를 켜고 일반 역할의 접근권한을 제거한다.

## 적용 후 자료가 채워지는 시점

격자 소속은 관할 변경 이력이 저장되면 계산에 즉시 반영된다. 이미 수집된 칸의 기관별 예보 합계는 다음 정기 재계산 때 갱신된다. 새로 포함된 좌표 38칸의 예보는 **다음 단기예보 발표의 정기 수집부터** 채워진다. 제외되는 고유 좌표는 0칸이다. 기존 발표의 좌표 순서나 저장된 기상 배열을 바꾸면 위치와 값이 어긋나므로 이를 수정하지 않는다. 새 칸을 실제로 수집하기 전까지는 962칸 전체의 예보가 모두 있다고 표시하면 안 된다.

새로운 노선을 추가하거나 좌표를 변경하는 작업에서는 `tools/build_section_grid.py`로 관계를 다시 생성하고 서버 관계도 같은 검토 절차로 갱신해야 한다. 일반적인 지사 간 노선 소속 변경은 재생성이나 배포 없이 이력으로 자동 반영된다.

## 사용자 선택: 노선의 4km 범위에 격자 일부라도 접촉

| 범위 | 전국 고유 격자 | 지사별 편입 관계 합계 |
|---|---:|---:|
| 현재 운영 | 924 | 1,059 |
| 노선 연동 수정 후·기존 수동 유지 | 962 | 1,111 |
| 4km 자동 편입, 수동 적용 전 | 2,000 | 2,808 |
| **4km + 기존 수동 편입·제외 유지** | **1,992** | **2,796** |

사용자가 선택한 ‘일부라도 닿음’ 기준은 격자 사각형과 현재 관할 노선 사이의 최단거리가 4,000m 이하인 경우다. 한국 평면좌표계 EPSG:5179에서 계산했다. 원본 선과 격자 모서리를 변환한 수치 계산으로, 현장 측량의 정확성을 뜻하지 않는다. 격자 일부만 접촉해도 포함되므로 중심점은 노선에서 4km보다 멀 수 있다. 참고로 중심점 기준은 자동 1,219칸/수동 유지 시 1,207칸이지만, 이번 선택 기준은 아니다.

최종 1,992칸은 현재보다 **1,068칸 (+115.6%, 약 2.16배)**, 노선 연동 수정 후보다 **1,030칸** 많다. 영암은 자동 17→48칸, 합천은 20→43칸이다. 두 지사는 직접 수동 예외가 없어 이 수량이 그대로 유지된다.

4km 확대는 **계산만 했으며 적용하지 않았다.** 현재 전국 격자를 먼저 받는 수집 방식에서는 평상시 기상청 요청 횟수가 격자 수만큼 늘지 않는다. 저장량과 지사별 화면 전송량은 증가한다. 지사별 편입 관계 합계는 현재의 약 2.64배지만 실제 Egress는 이용 화면·신규 조회 수·압축·캐시 등에 따라 달라져 같은 비율이라고 단정할 수 없다. 주변 산지의 예보도 기관 최댓값에 들어가는 의미 변화가 있다.

## 검증 및 남은 절차

- 구간별 격자 생성과 기존 기본 편입 재현, 소속 이동, 신설 기관, 공유 칸, 수동 예외를 검사했다.
- 별도 로컬 PostgreSQL 호환 DB에서 SQL 11/11 통과. 운영 좌표 지문과 로컬 자료도 일치했다.
- 운영 서버는 읽기 전용 비교만 수행. SQL 적용·4km 확대·화면 배포는 하지 않았다.
- 전체 24개 시험 묶음의 **435/435 항목 통과**. 프로그램 소스 변경 없이 완료했다. 별도 SQL 검사도 11/11 통과했다. 사용자가 검토 SQL 적용을 승인하면 서버 적용 → 실서버 검증 → 화면 배포 → 새 지사 정기 수집 확인 순서로 진행한다.
