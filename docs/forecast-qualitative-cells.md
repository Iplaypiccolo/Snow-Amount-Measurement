# 먼 3시간 예보 칸과 정성 강도 표시 (73)

2026-11-06 사용자 요청: 기상청처럼 받은3시간 칸부터 표시하며, 먼 날짜의 칸도 숨기지 않는다. 기존 ‘정성 구간은 시간 칸 전체 제외’ 정책을 대체한다.

## 범위와 표현

기상청은 연장 기간도3시간 간격으로 제공하되 PCP/SNO를 양이 아닌 강도 코드로 제공한다. 서버에는9일 기온·확률까지 이미 저장돼 있었으나 화면이 눈/비null 또는코드 구간이면 칸 전체를 버려8일에서 끝났다. 앞서8일 끝을 정상이라고만 설명한 것은 표시 정책과 자료 제공 범위를 충분히 구분하지 못한 설명이었다.

- 기온·확률: 기존처럼 구간의 최저 기온·최고 확률.
- 정량 구간: 기존3시간 합계(cm/mm)와 미량 상한 유지. 가까운SNO2는 기존대로2cm이며 정성 코드로 바꾸지 않는다.
- 정성 구간: SNO1=보통 눈(시간당1cm 미만),2=많은 눈(시간당1cm 이상); PCP1=약한 비(시간당3mm 미만),2=비(3~15mm 미만),3=강한 비(15mm 이상). 구간에서 가장 강한 코드를 표시하고 합산하지 않는다. 마우스 설명에 시간당 기준과3시간 누적량이 아님을 명시한다.
- 코드0/정량0은 빈칸. 결측·알 수 없는 코드값을0이나 수치량으로 추정하지 않는다. 기온/확률 등 유효 자료가 있으면 시간 칸은 유지한다.
- 정량·정성 혼합 칸은 ‘정성 포함’으로 표시하고 합계량을 만들지 않는다. 빈 시각은 기존처럼 제외하며 실제 범위를 표기한다.

기존 자동 갱신(수집 중3분·완료 후10분, 선택 격자/보이는 창만)을 사용한다. 하루치 전체 완료를 기다리지 않는다. ‘바로 반영’은 다음 자동 확인에 준비된 칸을 추가하는 의미이며 기상청 수집을 추가 호출하는 방식은 아니다.

## 서버 변경

73은 기존 `forecast_cell_tail(int,int)`의 JSON 칸에 `snow_code`·`pcp_code`만 추가한다. 원래 반환값은 그대로이며 기존 함수 인자·권한·로그인/격자 검사·정량 경계·5종 준비 자료 선택도 유지한다. 테이블/수집 예약/기상청 API/확정 자료는 변경하지 않는다. 적용 전 함수 지문이 달라지면 중단한다. SQL 전체는 적용 전에 사용자에게 제시했다.

코드는 유효 범위를 원자료에서 검사하므로-999를0으로 바꾸지 않는다. 모든 코드 시각에서 해당 변수의 코드가 유효할 때만 최대 강도를 반환한다. 정성/혼합의 기존 합계null은 유지한다.

## 검증과 근거

- 계산36/36: 기존24개 시작 시각, 정량/코드 분리,0·알 수 없는 코드, 혼합, 한 칸 추가, 입력 불변.
- 화면: 별도 두 창, 데스크톱/휴대전화 글자·가로 스크롤, 정성 한 칸 자동 추가 시 강도/기온/확률 표시.
- 로컬 SQL11/11: 기존 응답에서 새 항목을 제외하면 동일, 코드 최대 강도와null 합계, 기온/확률,0·결측·잘못된 코드, 한 칸 추가/collecting, 권한/격자 검사.
- 전체 시험 및 실제 서버/공개 파일 결과는 handoff에 기록한다. 실제 눈/비가 있는 원자료와 날씨누리의 동일 격자·동일 시각 강도 대조는 별도 미확인이다.
- 전체459/459(505.9초). 실서버 authenticated 읽기로50,67의9일 코드8칸 반환 확인(10,341bytes), 이 응답을 로컬 화면에 넣어11/9 22~24까지 표시되는 것을 확인했다. 다른 화면 데이터는 모의이며 운영 사용자 입력은 바꾸지 않았다. 함수 본문 후보 일치·ACL·확정63건 지문 불변, 보안 경고 추가 없음.
- 공개 index.html·forecast/ui.js·forecast/series.js 내용이 배포e37e87e와 일치함을 확인했다. 실제 날씨누리와 동일 지점/시각의 강수 강도 비교는 위 검증과 구별한다.
