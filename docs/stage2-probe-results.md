# 2단계 선행 조사 결과 (2026-11-05 KST)

## 완료한 범위
사용자 승인 후 collect-forecast에 지정 발표/예보 시각을 조회하는 probeAt 분기만 추가했다. 기존 수집·인증 경로를 유지했고 운영 수집 범위는 아직 27시간이다. 서버 함수 v4 → v5 배포 완료, 배포 소스와 시험한 소스의 일치 확인. 스키마·예약·예보 계산 SQL은 변경하지 않았다.

전체 자동 시험 23묶음 386/386 통과(696초), 시험 중 소스 변경 없음. 이 중 함수 시험은 기존18+신규16=34/34. 실제 기상청 요청은 승인한 24건만 실행했으며 모두 HTTP200·격자37,697개로 응답했다. 서버 토큰/기상청 키는 조회 결과·파일에 출력하지 않았다.

## 확인한 내용과 확인하지 못한 내용
- 2026-11-04 02시 발표의 11-07 00~03시, 23시 발표의 11-08 00~03시 기온은 모두 다양한 값이 있었다. 이 표본의 01·02시를 빈 시각이나 3시간 간격이라고 단정할 수 없다. 인접 시각의 기온 가용성만 확인했으며 눈·비의 시간별 정량 생산을 증명하지는 않는다.
- 네 가지 발표/발효 조합에서 SNO·PCP는 유효 격자 값이 모두0이었다. 따라서 눈의1·2가 cm인지 정성 코드인지 이번 실측으로 판별하지 못했다. 다른 발표의 끝부분·중간 누락도 이번24건에서 재현한 것은 아니다.
- 공식 2024-11-28 변경 PDF는 연장 구간 SNO·PCP 정성 코드와 3시간 생산을 명시하고, API 설명 본문은 1시간 제공으로 적고 있다. 공식 2025 설명에서도 연장 구간의 강수 강도를 설명한다. 현재 숫자 응답과 시간별 의미가 일치하는지 더 대조해야 한다.
- **단계 코드일 가능성이 있는 눈·비 값을 cm/mm로 합산하는 수집/계산 변경은 아직 진행하지 않는다.** 수집 확대에 들어갈 때 발표·예보 시각·해석 구분을 함께 보존하는 설계가 필요하다. 원래 합의한 시간별 최신 완성 자료 선택과 기존 발표 보존도 여전히 필요하다.

## 사용량 실측과 예상
- 1건 본문341,297bytes, 24건 합계8,191,128bytes(약8.19MB). 함수 안 조회/요약 시간85~532ms. 인증·함수 시작·pg_net 대기·헤더·압축 전송량은 이 값에 포함되지 않는다.
- 재시도 없는 예보 수집 예상: 현재4,536 → 확대6,916요청/일. 이번 본문 크기가 같다는 가정이면 약2.36GB/일. 이 수치는 다른 수집기·재시도와 실제 과금 전송량을 포함하지 않는다.
- 평균3회 시도면 예보만20,748요청/일로 일반회원20,000건을 초과한다. 예산 상한과 요청 계측 없이 제한에 문제없다고 확답할 수 없다. Supabase 월 Egress 실제 잔여량은 미확인이다.

## 운영 자료 확인
- 확정 자료63건의 전체 내용 지문은 조사 전후 동일(이번 동일한 정렬/직렬화 기준9474b5678fae2fee0944c90247e8e4c9).
- fc_apply 함수 정의 지문은89e1730d8102df25ecf1fd91f50079a2로 1단계 적용 상태 유지.
- probeAt은 계획 RPC·예보 저장·실패 기록을 부르지 않는다. 호출을 위해 기존 pg_net 내부 큐/응답 기록은 발생했다.
