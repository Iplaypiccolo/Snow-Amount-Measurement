# 일별 보강 수집기 (2026-11-06)

SQL77 기반의 수집기 `collect-daily-aux` v1을 배포했고 **20시 발표·11/7~10 최저/최고8개 파일의 첫 실제 저장을 완료**했다. **예약 SQL78은 운영 미적용·사용자 확인 대기**다. 현재 일별 화면은 아직 기존2창이다.

## 필요한 부분만 추가

새 Edge Function `collect-daily-aux`가 기존 수집기의 격자 상수/주소/시각 변환만 가져온다. 기존 `collect-forecast`/`collect-midterm`의 실행 코드·계획·완료 판정은 수정하지 않았다. 기본 요청은 공식TMN/TMX이며 SKY는 명시적으로 선택할 때만 받는다. 예약안의 본문은 `sky:false`로 고정했다.

- 서버 전용 수집 토큰만 허용한다. 임의URL/구역/발표/예보시각/키를 입력받지 않는다. 키는 기존 `KMA_AUTH_KEY`만 서버 환경에서 사용한다.
- SQL77의 최신 발표·격자 순서·미수집 목록을 확인한 뒤 해당 파일만 요청한다. 이미 받은 자료는 다시 요청하지 않으며, 작업 시간이 부족하면 완료한 자료를 보존하고 다음 호출에서 이어간다.
- 전국37,697개 숫자를 모두 검증한 뒤 필요한 격자만 저장한다. 잘린 응답·잘못된 숫자/코드·범위를 거부한다. HTTP 오류나 `dfs_file_read` 문구를 빈 자료 성공으로 저장하지 않는다.
- 전국이 모두0이거나 모두 센티널이면 미제공 숫자 파일로 처리한다. 나머지 정상 파일의 개별0℃는 그대로 보존한다. SKY의0은 결측으로 처리한다. 빈 숫자 파일의 재확인은 SQL77의30분 간격·발표/항목/시각별3회 제한을 따른다.
- 통신/5xx는 한 번만 재시도한다. 인증·형식 오류는 반복하지 않는다. 원본 오류/주소/키를 응답이나 로그로 보내지 않는다.
- 실제 KMA 요청 수/바이트/재시도만 기존 사용량 계측의 단기 항목에 합산한다. 한국 날짜가 바뀌면 나눠 기록한다. 사용량 기록 실패로 이미 저장한 예보를 실패 처리하지 않는다.
- 인증·DB 응답 시간을 포함해 새 다운로드를 일찍 중단하고, 저장·계측의 시간을 남긴다. RPC의 정상 빈 응답도 처리한다. [공식 실행 제한](https://supabase.com/docs/guides/functions/limits)을 확인했다.

## 자동예약 검토본78

[실행 SQL 원문](sql/daily_aux_schedule_78.review.sql).

- 매시00·20·40분에미수집 여부를 확인한다. 없으면 DB에서 종료하며 Edge/KMA를 호출하지 않는다.
- 기존 예보/중기 예약은 유지하고 `collect-daily-aux` 예약 하나만 추가한다.3분 이내 중복 전송도 막는다.
- 기본 기온만 수집한다. SKY는 켜지 않는다. DB는 서울에 유지하고 함수 실행만 도쿄로 지정한다.
- 사용자 확인 후 적용하며 첫 실행도 포함한다. 먼저 실제 수집을 마쳤다면 첫 실행은 추가 요청 없이 끝난다.

처음 전체 실행에서는 기존 화면 시험이22시대 동적 자료에22~24칸이 반드시 있다고 가정해 실패했다. 화면 코드는 바꾸지 않고 해당 시험의 예보창만 고정했고 단독 재실행은 통과했다. 뒤이어 새 파서의 끝 쉼표 호환성을 보강해 진행 중 검증을 중단하고 최종 코드로 전체 시험을 다시 시작했다. 중간 실행을 최종 전체 통과 결과로 사용하지 않는다.
