# 첫 화면 로그인 잠금 · 자동 로그인 · 아이디 저장

`https://iplaypiccolo.github.io/Snow-Amount-Measurement/` 의 **첫 화면 전체**(강설량 측정, 기관별 관할 고속도로, 예보 격자 편입, 장비 지원)는 로그인해야 열립니다.
(자동 시험: `tests/test_login_gate.py` 12항목)

## 1. 어떻게 동작하나
1. 주소를 열면 **로그인 화면**만 보입니다. 로그인하기 전에는 화면도, 자료 파일(`data/*.json`)을 불러오는 것도 하지 않습니다.
2. 아이디·비밀번호를 입력하면 Supabase(서울)가 확인하고, 맞으면 **로그인 열쇠(토큰)** 를 내려줍니다. 이 열쇠를 이 브라우저에 보관합니다.
3. 열쇠는 약 1시간마다 만료되지만 **자동으로 새로 받습니다.** 그래서 쓰는 동안 다시 묻지 않습니다.
4. 관리자가 비밀번호를 바꾸거나 계정을 비활성화하면 서버가 그 계정의 열쇠를 모두 무효로 만들어서, 다음에 열 때 다시 로그인하게 됩니다.
5. 화면 오른쪽 위에 `이름 (역할)`, 관리자는 **관리** 링크, 그리고 **로그아웃** 버튼이 보입니다.
6. **관리 콘솔에서 비밀번호를 일괄 설정한 계정**은 바로 로그인됩니다(기본값). 관리자가 "처음 로그인할 때 바꾸게 하기"를 켜서 정했거나 "임시 비밀번호 발급"으로 받은 비밀번호로 로그인하면 "새 비밀번호를 먼저 정해야 합니다" 화면이 나오고, **새 비밀번호 정하기**로 관리 콘솔(`/admin/`)에 갑니다. 바꾸기 전에는 화면을 쓸 수 없습니다.

## 2. "쿠키"? "캐시"? — 어떤 것을 쓰나 (용어 정리)
처음 말씀하신 "캐시, 쿠키"는 로그인 상태를 기억하는 방법으로는 **적절하지 않아서, 가장 알맞은 "브라우저 저장소(로컬 스토리지)"** 를 썼습니다.

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **캐시(cache)** | 자주 쓰는 파일(이미지·스크립트)을 다시 받지 않으려고 브라우저가 **임시로 보관**해 둔 것 | 쓰지 않음. 로그인 정보를 담는 곳이 아님(언제든 지워져도 되는 곳) |
| **쿠키(cookie)** | 브라우저가 서버에 요청할 때마다 **자동으로 함께 보내지는** 작은 정보. 보통 "서버"가 로그인 상태를 관리할 때 씀 | 쓰지 않음. 이 사이트(GitHub Pages)에는 우리 서버가 없고, 쿠키는 요청마다 따라가서 오히려 노출될 곳이 많아짐 |
| **로컬 스토리지(브라우저 저장소)** | 이 브라우저 **안에만** 저장되고 서버로 자동 전송되지 않는 저장 공간. **탭을 닫아도 남음** | **자동 로그인**과 **아이디 저장**에 사용 |
| **세션 스토리지** | 위와 같지만 **탭을 닫으면 사라짐** | 자동 로그인을 켜지 않았을 때 로그인 열쇠를 여기에 보관 |

화면의 이름도 한국 서비스에서 가장 익숙한 말로 통일했습니다: **"아이디 저장"**, **"자동 로그인"**, (비밀번호는 "저장"하지 않으므로 "비밀번호 저장" 같은 말은 쓰지 않음), 내부 용어 "세션·토큰"은 화면에서 "로그인 상태·열쇠"로 풀어 씁니다.

## 3. 아이디 저장
- 체크하고 로그인하면 **아이디만** 이 컴퓨터에 저장합니다. 다음에 열면 아이디가 채워져 있고 비밀번호 칸에 커서가 있습니다.
- 체크를 풀고 로그인하면 저장된 아이디가 지워집니다. 로그아웃해도 저장된 아이디는 남습니다(체크한 경우).
- 비밀번호는 어디에도 저장되지 않습니다. (브라우저가 자체적으로 제공하는 "비밀번호 저장" 기능은 사용자가 따로 켠 경우에만 동작합니다.)

## 4. 자동 로그인
- 체크하고 로그인하면 **로그인 열쇠를 이 컴퓨터에 남겨서**, 브라우저를 껐다 켜도 비밀번호를 다시 묻지 않습니다.
- **유지 기간**: 관리자 **7일**, 그 밖의 계정 **30일**. 기간이 지나면 다시 로그인해야 합니다. (관리자는 권한이 커서 더 짧게 했습니다)
- **다른 컴퓨터·다른 브라우저에서는 적용되지 않습니다**(그 브라우저 안에만 저장되므로).
- **공용 컴퓨터에서는 켜지 마세요.** 다음에 그 컴퓨터를 쓰는 사람이 같은 계정으로 들어올 수 있습니다. 끄려면 **로그아웃**을 누르면 열쇠가 삭제됩니다.
- 기본값은 **꺼짐**입니다. 켜지 않으면 탭을 닫을 때 로그인 상태가 사라집니다(같은 탭에서 새로고침은 유지).
- 한 탭에서 로그아웃하면 **열려 있는 다른 탭도 즉시 로그인 화면**으로 돌아갑니다.

## 5. ⚠ 꼭 알아 둘 한계: 이 잠금은 "화면"을 가리는 것이지 "자료"를 지키는 것이 아닙니다
이 사이트는 GitHub Pages 라서 **파일을 그대로 내려주는 정적 사이트**입니다.
- 지금 화면이 쓰는 자료(`data/roads.json`, `snow_data.json`, `sections.json` 등)는 **공개 저장소의 파일**이라서, 주소를 아는 사람은 로그인 없이도 파일을 직접 내려받을 수 있습니다. 로그인 잠금은 이것을 막지 못합니다.
- 이 자료는 고속도로 선, 기상청 관측 자료, 관할 구간처럼 원래 공개된 성격이거나 가상 데이터입니다.
- **진짜 보호가 필요한 자료(실제 장비 차량번호, 지사별 요청·편성, 접속 기록)는 처음부터 Supabase 에만 넣습니다.** 그 자료는 서버가 로그인 여부와 역할을 매번 검사해서, 주소를 알아도 로그인 없이는 한 줄도 받을 수 없습니다. (권한 규칙 시험 103항목)
- 따라서 **"기준정보 이전 → 화면 연결" 단계가 끝나야** 첫 화면의 자료까지 로그인으로 보호됩니다. 그 전까지의 잠금은 "사용자 구분과 접근 기록을 위한 문"입니다.

## 6. 보안 설계
- 로그인 열쇠는 이 브라우저 저장소에만 있고 **주소·기록·서버 로그에 남기지 않습니다**. 자동 시험이 저장소·화면·주소에 비밀번호가 없는지 확인합니다.
- 이름에 `<script>` 같은 글자가 있어도 **글자로만 표시**합니다(자동 시험).
- 여러 탭이 동시에 열쇠를 새로 받으려다 꼬이지 않도록 **한 번에 하나씩** 갱신합니다(Web Locks).
- 서버에 연결이 안 될 때는 로그인 정보를 지우지 않고 **"다시 시도"** 를 보여 줍니다(회사 네트워크에서 `supabase.co` 가 막힌 경우에도 원인을 알 수 있도록 안내 문구에 적음).
- 장비 지원 화면(`/equipment/`)을 주소로 직접 열면 로그인 정보가 없을 때 **안내만** 보입니다. (첫 화면에서 로그인하고 들어오면 항상 통과)
- 한계: 자동 로그인은 이 컴퓨터의 저장소에 열쇠를 남기므로, 그 컴퓨터가 악성 프로그램에 감염되었거나 화면 코드에 보안 구멍이 있으면 열쇠가 노출될 수 있습니다. 그래서 관리자 유지 기간을 짧게 하고 기본값을 꺼 두었습니다.

## 7. 문제가 생기면
| 증상 | 원인·해결 |
|---|---|
| "서버에 연결하지 못했습니다" | 인터넷 또는 회사 네트워크에서 `supabase.co` 가 막힘. [다시 시도]. 계속되면 보안 담당에게 `*.supabase.co` 허용을 요청 |
| "로그인이 만료되었습니다" | 자동 로그인 기간이 지났거나 관리자가 비밀번호를 바꿈/비활성화함. 다시 로그인 |
| "이 계정은 아직 등록되어 있지 않습니다" | 가입만 되어 있고 관리자가 역할을 연결하지 않은 계정. 관리자에게 문의 |
| 비밀번호를 잊음 | 관리자가 **관리 콘솔 → 계정 관리 → 임시 비밀번호 발급** 또는 **비밀번호 일괄 설정** |

## 8. 새 로그인 화면 + 차로차로 친구들 인트로 (2026-10-19 기본 화면으로 적용)
- 미리보기(`?intro=preview`)로 확인한 뒤 **2026-10-19 기본 화면으로 적용**했습니다. 문제가 생기면 주소 끝에 **`?intro=off`** 를 붙이면 예전 로그인 화면(인트로 없음)이 나옵니다. 완전히 되돌리려면 `index.html` 의 `login/login-v2.css`·`login/intro-loader.js` 두 줄을 빼면 됩니다.
- 순서: 로그인 화면 대신 인트로(6.3초, 차로차로 친구 6명) → 끝나면 겨울 색감의 새 로그인 화면이 차례로 나타남.
  - 인트로는 화면 가운데에서 재생. **정렬 단계(5.15~5.85초)에 친구들이 한 번만 작아지며 최종 자리로 곧장 이동**(PC: 왼쪽 / 휴대폰: 상자 아래)하고, 같은 순간 로그인 상자가 나타남(PC: 오른쪽 / 휴대폰: 위). 건너뛰면 정렬 단계부터 이어 재생.
  - 방법: 인트로 그림판을 화면 전체로 두고(재생기 `center` 옵션), `intro-loader.js` 의 `relayout()` 이 인트로 정렬 단계의 도착점(정렬 키)을 화면의 빈 곳으로 바꿔 넣음. 창 크기를 바꾸면 다시 계산.
  - 최종 크기는 모두가 슬로모션 때 키보다 조금 작게(대형 키 × 0.49 × 최대 1.88). 휴대폰: 상자 아래 48px 이상 띄우고 남은 공간의 60% 높이, 폭은 화면의 85%.
  - 시스템 이름 같은 큰 글자는 두지 않음. 로그인하면 친구들도 사라짐.
  - 인트로는 **매번** 재생(사용자 결정). 자동 로그인으로 들어오는 사람은 로그인 화면을 거치지 않으므로 보지 않음.
  - 건너뛰기: 오른쪽 아래 버튼 · 화면 아무 곳 클릭 · Esc/Enter/Space. 그림을 5초 안에 못 불러오거나 오류가 나면 인트로 없이 바로 로그인 화면.
  - 인트로 동안 로그인 칸은 잠금(inert) → 안 보이는 칸에 글자가 들어가지 않음. 인트로가 끝나면 아이디(저장된 아이디가 있으면 비밀번호) 칸에 커서.
  - '움직임 줄이기'(운영체제 설정)를 켠 컴퓨터는 간소화한 인트로, 화면 움직임(눈·시차·자석 버튼·등장 효과) 없음.
- **로그인 판단 코드는 그대로**입니다(`auth/auth.js`·`auth/gate.js` 수정 없음). 새 화면은 `login/login-v2.css` 가 `html.ss-v2` 일 때만 모양을 바꾸고, `login/intro-loader.js` 가 배경 장면·인트로를 얹습니다.
- 비밀번호 칸은 키 종류·글자 수에 반응하지 않습니다(움직임 효과는 포인터 위치에만 반응).
- 아래 줄 친구들의 키보드·마우스 반응, 로그인 성공 모션은 사용자가 따로 정할 예정(아직 없음).
- 파일: `login/intro-loader.js`(시작·건너뛰기·배경 장면) · `login/login-v2.css` · `login/intro/`(재생기·배치표·캐릭터 6명·효과 그림, 약 0.9MB — 인트로를 볼 때만 받음).
  `login/intro/` 는 직접 고치지 않고 차로차로 저장소에서 `python tools/build_login_intro.py <차로차로 저장소 폴더>` 로 다시 만듭니다(그림은 WebP 로 줄임). 그다음 `python tools/stamp_assets.py`.

## 9. 친구들 마우스 반응 (2026-10-19 기본 적용 · 비상용 `?mouse=off` 면 끔)
- 인트로가 끝나 자리 잡은 친구들이 평소에도 커서를 따라봄(눈·눈썹·머리/몸, 귀·날개·꼬리는 늦게) + 가끔 깜빡임. 친구 주변에 커서가 잠깐 머무르면 그 친구만의 반응을 한 번 함(커서가 왼쪽/오른쪽이냐에 따라 동작 방향이 바뀜, 길통이는 한 방향).
