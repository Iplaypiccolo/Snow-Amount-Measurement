# 예보 격자 편입 — 동작 규칙 (사람이 읽는 문서)

강설량 측정 페이지의 **"예보 격자 편입"** 탭이 어떻게 동작해야 하는지 정리한 문서입니다.
(자동 테스트: `tests/test_grid_core.js`, `tests/test_grid_ui.py`)

## 1. 왜 필요한가
기상청 단기예보는 **5km × 5km 격자(칸)** 단위로 줍니다. 기관별 적설 예보를 만들려면 "어느 칸의 예보를 어느 기관이 쓸지"를 정해야 합니다.
이 탭에서 칸을 지도로 보고 직접 골라 기관에 **편입**합니다. 예보 수집은 **편입된 칸의 합집합만** 호출합니다.

## 2. 핵심 규칙
- **한 칸을 여러 기관이 함께 가질 수 있습니다.** (경계에 걸친 칸 등) 이때 예보는 칸마다 **한 번만** 호출합니다. 호출 대상 = 기관이 한 곳이라도 있는 칸의 수(합집합).
- 처음에는 **그 칸을 지나가는 관할 구간의 기관**이 자동으로 편입되어 있습니다. (고속도로가 지나는 1,072칸 중 934칸, 이 중 118칸은 여러 기관이 공유) 미지정 구간만 지나는 138칸은 기관 없이 후보로만 보입니다.
- **후보 칸**: 고속도로 칸의 이웃 1,389칸. 산 위 지점처럼 도로 바로 옆 칸을 고르고 싶을 때 씁니다. (지도 오른쪽 아래 "후보 칸"으로 숨길 수 있음)
- 민자 본부는 예보 대상이 아니라 이 탭의 기관 목록에 나오지 않습니다. 관할 고속도로 탭에서 만든 신설 기관은 여기서도 보입니다.

## 3. 화면 사용법
1. 지도의 칸 색: **기관 색**(편입됨), **보라 굵은 테두리**(여러 기관 공유), **옅은 점선**(편입 안 된 후보), **주황 점선**(변경 대기), **분홍 굵은 테두리**(선택). 마우스를 올리면 칸 번호와 편입 기관이 보입니다.
2. 왼쪽 위 **요약**: 호출 대상 칸 수, 하루 호출 건수, **수집 분할** 횟수(예보를 몇 번에 나눠 읽는지)와 판정(초록/노랑/빨강). 판정 기준은 아래 "호출량 판정"을 보세요.
3. 왼쪽 목록에서 기관을 누르면 그 기관 칸만 진하게 보이고 지도가 그곳으로 이동합니다.
4. 이 탭은 **관리자 아이디로 로그인했을 때만 보입니다**(지사·장비 계정에는 탭도, 격자 자료 불러오기도 없음). "관리자 모드" 체크박스는 없고, 열려 있으면 바로 편집할 수 있습니다.
   - 칸을 누르면 선택/해제, **[▭ 영역 선택]**(또는 **Shift+드래그**)으로 사각형 안의 칸을 한꺼번에 선택, 기관을 열고 **[이 기관 격자 전체 선택]**도 됩니다. (Esc로 영역 선택 종료)
   - 아래 선택 바에서 **편입할 기관**을 고르고 **[편입 추가]**를 누르면 "변경 대기"에 쌓입니다.
   - **[편입 제외 (N칸)]**은 **기관을 고르지 않아도 됩니다.** 선택한 칸이 지금 속한 기관을 자동으로 찾아서 거기서 뺍니다(기관별 제외가 변경 대기에 따로 쌓임). 편입된 칸이 하나도 없으면 버튼이 꺼져 있습니다.
   - 선택한 칸 중 **여러 기관이 함께 편입한 칸**이 있을 때만 "어느 기관에서 제외할까요?" 창이 뜨고, 기관별로 체크(기본은 모두 체크)해서 [제외]를 누릅니다. 한 기관만 체크하면 그 기관에서만 빠지고 칸은 다른 기관에 남습니다.
5. 지도 오른쪽 위 **변경 대기 패널(한 곳)**: "● 변경 대기 N건", 쌓인 변경 목록(×로 그 변경만 취소), 변경 사유 칸, **[미리보기] [모두 취소] [저장]**이 이 패널에만 있습니다(왼쪽 아래에는 저장된 이력만). **[저장]**을 누르면 변경이 **서버(Supabase)에 바로 저장**되고 **모든 사용자에게 즉시 적용**되며, **"N건 저장되었습니다."** 한 줄만 나옵니다. GitHub 에 파일을 올릴 필요가 없습니다. 저장하지 못하면 이유가 나오고 변경 대기는 그대로 남으며 [다시 저장]·[파일로 받기]를 쓸 수 있습니다. 서버에서 이력을 읽지 못한 상태에서는 [저장]이 꺼집니다. 되돌리려면 반대로 편입/제외합니다(이력은 지우지 않고 쌓습니다).

## 4. 호출량 판정 (무료 플랜 기준)
| | 계산 | 판정 |
| 수집 분할 | 서버(Supabase) 함수 한 번 실행에 **CPU 2초**(공식 한도: 최대 150초·메모리 256MB)라 한 번에 모든 칸을 읽을 수 없어 나눠 읽음. **한 번에 약 100칸, 5분마다 한 묶음**(추정값) → 칸 수 ÷ 100 = 실행 횟수 | 참고용(판정은 아래 두 줄) |
| 3시간 안에 끝나는가 | 단기예보는 **3시간**마다 새로 발표됨 → 실행 횟수 × 5분 ≤ 180분 | 넘으면 빨강, 90분 넘으면 노랑 (예: 934칸은 10번·50분 → 초록) |
| 하루 호출 한도 | 칸 수 × 하루 8번 ≤ 1만 건 (공공데이터포털 개발 계정 기준, 앞서 확인한 값) | 넘으면 빨강, 8,000건(80%) 넘으면 노랑 (예: 1,250칸 = 10,000건) |
- 예: **300칸** = 3번·15분·하루 2,400건 → 충분. **934칸**(처음 상태 전체) = 10번·50분·하루 7,472건 → 초록(3시간 안에 충분, 한도의 75%). **1,251칸 이상**은 하루 한도를 넘어 빨강.
- ⚠ **"한 번에 100칸·5분"은 추정값**입니다(예보 응답 하나를 읽는 데 약 10ms 가 든다고 가정). 예보 수집 함수를 실제로 만든 뒤 재서 `grid/core.js` 의 `CELLS_PER_RUN`·`RUN_INTERVAL_MIN` 을 고치세요.
- 이전에는 "무료 Worker로는 3시간 안에 못 끝냅니다"가 나왔는데, 이는 **Cloudflare 무료 Worker(한 번에 외부 호출 50개 제한 → 40칸씩, 10분 간격)를 쓴다는 예전 계획**을 기준으로 한 판정이었습니다. 수집을 Supabase 로 하기로 하면서 기준을 위와 같이 바꿨습니다.
- 예: **300칸** = 8번·80분·하루 2,400건 → 무료로 충분. **934칸**(처음 상태 전체) = 무료로는 3시간 안에 못 끝남 → 칸을 줄이거나 유료 플랜이 필요.

## 5. 파일
| 파일 | 내용 | 누가 바꾸나 |
|---|---|---|
| `data/grid_assign.json` | 기본 편입(칸별 기관)과 후보 칸 | `tools/build_grid_assign.py` 가 생성 |
| 서버(Supabase) 표 `grid_events` | **저장된 변경 이력**(편입 `cellAdd`·제외 `cellRemove`). [저장]하면 쌓이고 모두 같은 이력을 읽음. 예전 `data/grid_changes.json` 은 서버에 연결하지 못할 때의 비상용 | 관리자(화면의 [저장]) |
| `grid/core.js`, `ui.js`, `style.css` | 계산 / 화면 / 디자인 | 개발 |

변경 파일 형식(`events` 배열):
```
{ "t":"add",    "cells":[[73,127],[74,127]], "to":"B012"   }    칸에 기관 편입
{ "t":"remove", "cells":[[73,127]],          "from":"B012" }    칸에서 기관 제외
```
각 이벤트에는 `at`(시각), `note`(사유)가 함께 저장됩니다. 없는 기관, 범위 밖 칸, 이미 같은 상태인 변경은 **무시**됩니다.

## 6. 격자 번호 계산
기상청 공식 람베르트 투영식을 그대로 썼습니다. (서울시청 = 60,127, 부산시청 = 98,76 이 맞는지, 모든 칸의 중심이 같은 칸으로 되돌아오는지, 칸 변이 약 5km인지 자동 테스트로 확인)

## 7. 아직 정하지 않은 것
- 예보를 **기관별로 합칠 때**(한 기관에 칸이 여러 개일 때) 쓸 값: 지금 계획은 "칸들 중 최댓값과 그 칸"
- 특보 구역과의 대응(칸 중심이 어느 시·군 특보 구역인지): 구역 경계 자료가 필요
- 칸 번호로 **현장 위치를 더 쉽게 알아보는 방법**(시·군 이름 표시 등)
