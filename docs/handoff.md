# 인계 메모 (handoff) — 채팅의 Claude 와 Claude Code 가 서로 알 수 있는 유일한 통로

**왜 필요한가**: claude.ai 채팅과 Claude Code 데스크톱 앱은 **서로의 대화 내용을 볼 수 없습니다.** 둘이 함께 보는 것은 이 저장소(GitHub)뿐입니다.
그래서 작업을 마칠 때마다 이 파일 맨 위(아래 "기록" 구역)에 항목을 추가하고 커밋·푸시합니다. 채팅의 Claude 는 새 대화를 시작할 때 이 파일을 먼저 읽습니다.

## 쓰는 법 (Claude Code 용)
작업이 끝나면 **"기록" 맨 위**에 아래 모양으로 추가하세요. 짧게, 사실만, 한국어로.
```
### 2026-10-05 · 제목 한 줄
- 한 일: (무엇을 바꿨나 — 파일 이름 포함)
- 이유/원인: (왜 그랬나, 버그라면 원인)
- 확인한 것: (실제 서버/사이트에서 확인한 것 / 시험만 통과한 것을 구분)
- 확인 못 한 것·남은 일:
- 서버에 한 변경: (SQL/함수 배포가 있으면 파일 이름. 없으면 "없음")
- 제안(채팅에서 정해야 할 설계): (있으면)
```
설계 변경이 필요해 보이면 구현하지 말고 **"제안"** 에만 적으세요. 비밀값(토큰·키·비밀번호)은 절대 쓰지 마세요.

## 쓰는 법 (채팅의 Claude 용)
새 대화를 시작하면 먼저: `git pull` → `CLAUDE.md` → 이 파일 → `git log -30` → `docs/decisions.md` 끝부분을 읽고 현재 상태를 한 단락으로 요약해 사용자에게 확인받는다.
사용자는 새 대화의 첫 문장으로 이렇게 말하면 된다: *"저장소 Iplaypiccolo/Snow-Amount-Measurement 의 CLAUDE.md, docs/handoff.md, 최근 커밋 30개를 먼저 읽고 현재 상태를 요약해 줘."*

## 현재 상태 (2026-10-03 기준, 채팅의 Claude 가 작성)

### 완료
- 서버(Supabase `snow-support`): 표 28개 + 구간 변경 요청 표, 권한 규칙(RLS)·접속 기록·불변 기록, 계정 61개(`admin-01`, `admin-02`, 지사 59개; 전부 비밀번호 변경 완료 상태), Edge Function `account-admin`(v3)·`import-reference`(v1).
- 기준정보 이전: 구간 1,011 · 관측소 260 · 지사별 관측소 384 · 격자 편입 1,070쌍을 DB 로 옮기고 파일과 일치 확인(`tools/reference_check.py`).
- 화면: 로그인 잠금(자동 로그인·아이디 저장), 관리 콘솔(비밀번호 일괄 설정 등), 관할 변경(관리자만) + 지사의 구간 변경 요청 + 관리자 알림, 예보 격자 편입(관리자만), 저장은 서버에 즉시·새로고침 없이 반영.
- 구간 선 끊김 수리(`tools/fill_section_gaps.py`), 신설 기관 번호 보존 버그 수정.
- 서버에 현재 쌓인 것: 관할 변경 이력 18건(신설 2 + 이동 16), 격자 변경 이력 5건, 구간 변경 요청 0건, 차량·일별 적설·예보는 0건(아직 안 옮김).

### 아직 안 된 것 (다음 단계 후보, 채팅에서 정함)
1. **화면이 기본 자료(구간·관측소·격자)를 DB 에서 읽기** (지금은 파일을 읽음. DB 에 동일 사본이 있음)
2. 장비 지원 화면을 서버로 옮기기(지원 회차, 서버 권한 검사)
3. 예보·특보 수집(Edge Function + 스케줄, 공공데이터포털). 격자 화면의 "수집 분할 100칸·5분"은 **추정값** — 실제로 재서 `grid/core.js` 의 `CELLS_PER_RUN`·`RUN_INTERVAL_MIN` 을 고칠 것
4. 1주 미사용 시 자동 정지 방지 + 백업 내려받기 자동화(무료 플랜은 자동 백업 없음)

### 열린 질문 (사용자가 정해야 함)
- 신설 기관 `영암`(번호 `10`)·`민자`(번호 `11`)의 번호를 정식 형식(`B060`, `B061`)으로 정리할지(이력을 건드리는 일이라 하지 않음)
- 구간 선 끊김 중 600m 이하 짧은 곳을 직선으로 이을지(지금은 실제 도로망으로 이을 수 있는 139곳만 이음, 남은 곳은 `docs/section-gaps-report.md`)
- 장비 지원 화면의 실제 사용 시작 시점

## Claude Code 의 첫 과제: **실제 서버·사이트에서 확인하기**
채팅의 Claude 는 사이트(`github.io`)와 Supabase 에 접속할 수 없어서 아래를 **가짜 서버로만** 시험했습니다. 사용자 PC 에서 확인해 주세요. 확인한 결과를 아래 "기록"에 적으세요.
(비밀번호는 파일에 쓰지 말고 사용자가 알려 주는 대로 환경변수로만 쓰세요. 읽기만 하는 확인부터 하세요.)

- [ ] 사이트가 열리고 로그인 화면이 뜬다 (`https://iplaypiccolo.github.io/Snow-Amount-Measurement/`), 브라우저 콘솔에 오류가 없다
- [ ] `admin-01` 로그인 → 4개 탭 + 상단 "관리" 링크, 로그아웃, 자동 로그인(체크 시 새 탭에서도 유지)
- [ ] 지사 계정(예: 비밀번호 설정이 끝난 `exchungju`) 로그인 → **예보 격자 편입 탭이 없다**, 관할 탭은 "변경 요청 가능"
- [ ] 지사 계정으로 구간을 골라 **[구간 변경 요청]** 을 보낸다 → 관리자로 로그인했을 때 **알림창**이 뜬다 (현재 요청 0건이라 한 번도 실서버에서 확인 못 함)
- [ ] 관리자가 요청을 **[이동 준비] → [저장]** 하면 요청이 "승인"으로 바뀐다
- [ ] 관할 변경 저장 후 **새로고침 없이** 통계·관측소 지도가 바뀐다
- [ ] 중앙고속도로 밀양~삼랑진 구간의 선이 끊기지 않고 이어져 보인다
- [ ] 격자 탭에서 [편입 제외] 가 기관 선택 없이 동작하고 저장 후 "N건 저장되었습니다." 한 줄만 나온다
- [ ] (읽기 전용 SQL) `tools/reference_check.py` 로 만든 SQL 을 Supabase 에서 돌려 모두 `true`
- [ ] 회사 네트워크가 아닌 곳에서도 같은지(사용자 PC 는 회사망이 아니므로 **회사망에서 `supabase.co` 가 막히는지는 여기서 알 수 없음** — 사용자가 회사 PC 브라우저로 직접 확인해야 함)

이 확인을 자동으로 반복할 수 있게 `tools/live_check.py`(Playwright 로 실제 사이트에 읽기 위주 확인)를 **Claude Code 가 직접 만들고 시험해 보세요.** 채팅의 Claude 는 접속할 수 없어 시험하지 못한 상태라 만들지 않았습니다.
