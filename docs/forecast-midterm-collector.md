# 중기예보 수집 준비 (75)

**현재 상태(2026-11-06 19:40 KST): 수정SQL75 승인·운영 적용 완료. 자동예약 활성화, 날씨·기온 모두18시 발표 수집 완료(135/1,218행).** 아래 검토/승인대기 문단은 당시 단계 기록이며, 마지막 적용 완료 절을 따른다. 일별 화면은 후속 단계다.

`collect-midterm`은 기존 단기/초단기 수집 함수와 분리된 중기 원자료 수집기다. 기존 서버 키를 함수 안에서만 사용하며, 새 저장소74의 서버 전용 RPC로 정규화된 자료를 저장한다. 화면과 예보 격자의 중기 구역 연결은 이 단계에 포함하지 않는다.

## 받는 자료

기본1회에 최신 구역 목록과 지정한06/18시 발표의 육상 날씨·기온을 받는다. 중기 본문은구역별 요청 없이 전국을 한 번에 받는다. 정상적인 하루 기준 육상/기온4호출에 구역 목록2호출을 더해 기본6호출/일이다. 재시도·첫 수동 수집·앞으로 추가할 단기 보강은 이 계산에서 제외한다. 실제 계정의 남은 할당량을 확인한 수치는 아니다.

응답은2MB까지 전체를 해석한다. 앞서 점검용 함수에서80,000글자로 잘렸던 기온 응답을 사용하지 않는다. 시작/끝 표식, 발표시각, 날짜, 중복, 허용 코드/숫자, 구역별 전체 예보 칸을 검사한다. 최신 구역의C(도시)와 육상A 중 하위구역이 따로 있는 통합 구역을 제외한 코드를 대조한다. 실제06시 표본은240구역·육상15구역165칸·도시203곳1,421일자료다.

발표 당일 기준+4일 또는+5일부터+10일까지, 처음 제공되는 날짜를 따른다. +7일까지 반일(A02) 두 칸, +8~10일은 일 단위(A01) 한 칸이다. 이 검사는현행 공식 명세와 실제 표본을 기준으로 하며, 기상청이 기간/구역 계약을 바꾸면 새 원자료를 확인한 뒤 갱신해야 한다. 일 단위 자료를 오전/오후로 복제하지 않는다.

최저/최고의0은0으로 보존하고 결측 센티널은null로 바꾼다. 정상인 종류는 저장하되 실패한 종류는 기존 최신 자료를 유지한다. 본문이 없거나 잘렸으면 그 종류를 저장하지 않는다. 통신 오류/5xx만 함수 안에서1회 재시도하고, 인증 오류는반복하지 않는다. API주소·키·원본 오류는 반환하거나 기록하지 않는다.

## 예약 SQL 검토

[midterm_schedule_75.review.sql](sql/midterm_schedule_75.review.sql)은 **별도 사용자 확인이 필요한 새 SQL**이다. 현재 문서 작성 시 운영 미적용이다.

새 비공개 함수 `private.kick_midterm()`와 `collect-midterm` 예약1개를 추가한다. 매시15·35·55분, 최신06/18시 발표로부터15분 지난 시점의 미수집 종류만 요청한다. 이미 두 종류가 끝났으면 Edge Function이나 기상청 API를 호출하지 않는다. 종류 하나만 실패한 경우 그 종류만 다시 요청하고 구역 목록으로 완전성을 다시 확인한다. 동시 실행 잠금과3분 재전송 제한을 둔다. 새 업무 자료나 기존 수집 예약/함수/RLS는 변경하지 않는다.

첫 적용 때도 같은 함수를 한 번 실행하므로 미완료라면 즉시 시작하고, 이미 수집했으면 추가 요청 없이 끝난다. 예약은 UTC로 돌아가지만 발표 선택은 SQL에서한국 시각으로 계산한다.

## 실제 서버 결과와 남은 승인

`collect-midterm` v3를 snow-support에 배포했다. 비인증 호출은401로 거부한다. 정상 수집기준 기본6API호출/일, 실제 예약은아직 활성화하지 않았다. 프로그램 전체512/512, 시험 중 소스 변경 없음. 서버 지역 지정/SQL검사 보완은 별도 로컬15/15이며 운영 미적용이다.

새 함수의 서울(ap-northeast-2) 실행에서는 외부 API 응답 전 통신 실패(status0)가 반복됐다. 정상인 기존 점검 함수와 요청 설정을 맞춘 뒤에도 실패했다. 동일코드·동일키로도쿄(ap-northeast-1) 실행을 지정하자 구역240행·육상165행·기온1,421행(203도시)을06시 발표 전체로 정상 저장했다. DB는같은서울프로젝트다. 기존 점검 함수는서울에서도정상이라서울전체장애로단정하지않는다. 특정함수의외부연결경로차이까지좁혔으며기상청/플랫폼측정확한원인은미확정이다. 운영예약에는확인된도쿄실행헤더를사용하도록SQL수정본을제시했다.

18시 발표에서는 육상135행(+5~+10일)이 정상 저장됐으나, 기온은기존의 ‘아침 최저>낮 최고’ 거부 조건에걸려06시자료1,421행을보존했다. 기상청아침최저/낮최고는서로다른시간대다. 두값의순서만으로틀렸다고판단하면안된다. 프로그램의순서검사는제거했고, DB74의동일조건제거를75수정SQL에포함했다. 숫자범위/결측/권한은유지하며SQL은아직미적용이다. 값을바꾸거나서로교환하지않는다.
