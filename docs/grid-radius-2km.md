## 계산과 자료 생성

`tools/build_section_grid.py`가 한국 평면좌표계 EPSG:5179에서 노선과 격자 사각형 사이의 최단거리를 계산한다. 2,000m 이하인 칸을 구간별로 넣는다. 격자 중심점 기준이나 이웃8칸 일괄 추가가 아니다. 일부 신설 노선의 ‘대략 위치’ 좌표는 원본 그대로다. 생성 도구 의존성은 `pip install -r tools/grid_geometry_requirements.txt`로 설치한다.

`data/section_grid.json`은 version2 / radiusKm2 / method polygon-distance / crs EPSG:5179이며 1,025구간의 관계5,343개다. 원래 1km 샘플링 관계2,352개가 전부 포함됨을 검증했다. `--radius-km 0`은 옛 샘플링 재현용이다. 노선 소속 변경은 기존70의 이력 기반 계산으로 자동 반영된다. 좌표 자체나 구간을 새로 추가하는 작업은 자료 생성과 서버 관계 갱신을 함께 해야 한다.

## 서버 변경과 검증

SQL `supabase/migrations/20261105070232_highway_grid_2km_71.sql` (`highway_grid_2km_71`, 서버 버전 `20261105070232`)은 기존 비공개 `section_grid`에 구간-격자 관계2,991개를 추가했다. 기존 관계를 삭제하거나 함수·권한·관할/격자 이력·확정값·수집 예약·기존 발표 배열을 바꾸지 않았다. 검토한 노선/기존 관계/함수 지문이 달라지면 중단하도록 했다.

운영 조회 결과1,538칸/1,950관계가 로컬 화면 계산과 일치했다. 확정 자료 지문과 관할/격자 이력 수는 전후 동일했다. 로컬 SQL11/11, 전체25개 시험 묶음438/438(684.4초) 통과. 새 기하 검사3개는 중심점/경계 접촉 기준과 기존 샘플 포함을 확인한다. 격자 화면16개와 계산17개는 이동·신설·공유·수동 예외를 확인한다.

## 수집과 배포

격자는1,538칸으로 편입됐지만 적용 직후 아직 예보가 없는 좌표는 614칸이다. 여기에는 직전70 적용부터 대기 중이던 좌표도 포함될 수 있다. 새 좌표 예보는 다음 단기예보 발표의 정기 수집부터 채워진다. 기존 발표의 좌표/기상 배열을 재배열하지 않는다. 기상청 전국 응답을 받아 필요한 칸을 추리는 기존 수집 방식을 유지한다.
