# 격자별 24시간 이후 조회 (69)

2026-11-05 사용자 진행 지시 후 Supabase snow-support에 적용. `forecast_cell_tail_69` / `20261105000301`. Edge는 v6 그대로, 화면은 기존24시간이다. 이번 단계는 저장된 한 격자의 이후 예보를 계산하는 서버 조회다.

## 사용자 최신 화면 결정 (4단계 구현 예정)

- 24시간 예보와 이후3시간 예보를 **별도 모달 두 개**로 제공한다. 첨부 지침의한모달두줄계획을대체한다. 날짜별 합계·날짜 선택은 만들지 않는다.
- 3시간 칸은 한국 시각00·03·06시 등에 끝나도록 정렬한다. 기존 표가10시에 끝나면 이후 첫 칸은11~12시, 다음13~15시다.
- 대상 예보 시각의 시작·끝을 명시한다. 자정을 넘으면 `11/6 22시~11/7 00시`처럼 두 날짜를 표시한다. 범위 안 누락은 실제 시간 목록과 개수로 부분 자료임을 표시한다.
- 두 모달의 격자·24시간 기준을 맞추도록 응답에 기존 캐시와 범위를 함께 반환한다. 열기·전환 동작은 화면 단계에서 구현한다. **이 단계부터Sol Medium 추천**이며 시작 전 사용자에게 알린다.

## 변경한 함수

`public.forecast_cell_tail(p_nx int,p_ny int)` 추가. 기존 `forecast_grid`처럼 활성 로그인 계정만 호출한다. 현재 유효 격자 하나만 허용하고 비공개 본부·폐지 지사·비로그인을 제외한다. 임의 날짜 범위를 받지 않고24시간 뒤부터 최대120시간 창 안의 받은 자료까지만 읽는다.

`private.fc_hours`의6인자 내부 함수를 공통 선택기로 추가하고 기존4인자는 이를 호출하도록 변경했다. 기존4인자의 결과·권한은 유지한다. 새 조회에서는 선택 좌표가 있는 발표만 후보로 삼고 발표별 배열 순서에 맞춰 찾는다. 시각별5종 완성 최신 발표를 선택하고 미완성·빈 시각은 이전 준비 자료로 대체한다. 큰 값 배열은 발표/시각을 선택한 뒤 읽는다.

새 표·열·기상청 호출·수집 예약·Edge 변경은 없다. 조회 함수는 예보 원자료·24시간 캐시·확정 자료를 수정하지 않는다. 승인된SQL 원문은69 migration에 보존했다.

## 응답 계약

- `status`: `ok`, 캐시 없음/불완전 `no_data`,12시간 넘은 캐시 `stale`. `collecting`은 최신 발표 수집 중 여부다.
- `upper`: `tmfc`, `start_at`, `end_at`, `series`. `series`는 기존 `forecast_cells.series` 그대로다. `end_at`은24시간 창의 배타적 끝이며 이후 첫 대상 예보 시각이다.
- `tail`: `window_start_at`, 실제 받은 시각의 `first_at`·`last_at`, `bins`. 마지막 자료 이후의 빈 칸은 만들지 않는다.
- 각 칸: 대상 범위 `first_at`·`last_at`(양끝 포함), 정시 기준 `slot_end_at`, 범위의 `expected_hours`, 실제 개수 `hours`, 실제 시각 목록 `times`, 부분 여부 `partial`. 범위 처음이나 중간이 비어 있어도 대상 범위와 실제 시간을 구별한다. 완전히 빈 칸은 제외한다.
- `snow`·`pcp`는 정량 합계(cm·mm), `snow_hi`·`pcp_hi`는 기존 미량 추정 상한, `tmin`은 최저기온, `pop`은 최고확률이다. 미량 추정 방식 자체의 타당성은 이번 단계에서 새로 검증하지 않았다.
- `amount_kind`는 `numeric`/`code`/`mixed`, `quantity_hours`·`code_hours`로 포함 시간을 구분한다. 코드 시각이 하나라도 섞이면 눈·비 및 상한을null로 보내고 화면은`-`로 표시한다. 기온·확률은 유지한다. 코드 구분은68의발표/예보 날짜 규칙 그대로다.

## 권한 점검과 복구
