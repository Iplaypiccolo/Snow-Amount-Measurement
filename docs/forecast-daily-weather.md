# 일별 지역대표 날씨와 7일 통합 조회 (2026-11-07)

## 사용자 결정과 실제 확인

사용자는 가까운 날의 날씨·강수확률을 **공식 지역대표 원값**으로 선택했다. 최저·최고기온은 이미 수집 중인 선택 격자의 공식 TMN/TMX를 유지한다. 지역 날씨를 격자별 일별 날씨라고 표시하거나 시간별 확률의 최댓값으로 바꾸지 않는다. SKY 추가 수집도 켜지 않는다. 먼 날은 기존 중기 지역대표 자료를 사용한다.

단기 육상 두 API의 활용신청 완료 답변 후 기존 서버 키로 다시 확인했다. `fct_afs_dl.php`와 `fct_afs_dl2.php` 모두 실제 HTTP200,203개 구역×9반일=1,827행이다. 당시 최신 발표는11/6 17시,첫 반일11/6오후~끝11/10오후였다. API 응답 원문에 예보관 정보가 있어 저장할 항목에서 제외한다. dl2의 추가 체감온도도 필요 없어 **dl만 수집**한다.

공식 명세: [기상청 API허브 단기 육상예보](https://apihub.kma.go.kr/apiList.do?seqApi=10&seqApiSub=286). API 응답 도움말은 PREP4가2019-06-04이후 소나기임을 명시한다. 오래된 웹 설명의 눈/비와 혼동하지 않는다. DB01~04/강수코드/날씨 문구/확률 원값을 보존한다.

날씨누리의 가까운 날 일별 표는 격자 좌표와 더 최신 발표를 사용하는 경우가 있어 지역대표 원값과 같지 않았다. 영암11/7오전은 당시 날씨누리23시 구름많음10%,지역대표17시 맑음0%였고 대관령11/8오후도 문구/확률이 달랐다. 좌표만 바꾼 추가 비교에서도 날씨누리 값이 달라졌다. **완전히 같다고 주장하지 않는다.** 대표구역 코드/공식 이름·연결 대표지점/방법·날씨/기온의 개별 발표시각을 조회 결과에 포함한다. 앞선 ‘추가 신청 완료 알림 없음/403’ 상태는 해소됐다.

실제6지역54반일 표본은 예보관 정보만 제거해 `tests/fixtures/shortland_2026110617.txt`에 보존했다. 표본을 정규화한 결과도 원래 열의 날씨·확률과 일치한다. 전국 조회 원문의80KB 점검 응답은 잘려 있으므로 저장 입력으로 쓰지 않는다. 정식 수집기는 전체 응답과 시작/끝 표식을 검증한다.

## 예약과 사용량

앞서 안내한 ‘약3회’ 대신 **최신 자료 확인을 하루4구간**으로 고정한다. 한국05/11/17/23시30분에 확인,실패한 구간만40/50분 재시도한다. 이는 API가 반드시 하루4회 발표한다는 단정이 아니다. 동일한 발표라도 다음 확인 구간의 정상 최신조회 결과는 확인 완료로 기록하며,그 구간은 다시 Edge/API를 호출하지 않는다. 응답이 이미 저장한 발표보다 과거이면 덮어쓰거나 완료하지 않는다.

서버의 `cron.timezone=GMT`,DB`UTC`를 직접 확인했다. SQL의 예약은UTC02/08/14/20시이며 한국11/17/23/다음날05시에 해당한다. 잘못된 타임존에서는 적용을 거부한다. 함수만 도쿄,DB는 서울에 둔다. 기존 SQL78 기온 예약의 실제01:20/01:40KST 실행도 succeeded를 확인했다. SKY 캐시는 여전히0행이었다.

정상 추가량은 **KMA4회/일**,당시 응답174,040bytes 기준 다운로드 약0.70MB/일이다. DB→브라우저 전송량과 다른 수치다. 실패 재확인/통신 재시도는 별도이며 최대3진입×2요청×4구간=24시도/일(초기 수동 점검 제외)이다. 화면을 여는 사람마다 KMA를 호출하지 않는다. 하루4회·30일=정상120 Edge진입 정도이고,새 캐시는최신1행만 유지한다. 전체 무료 한도 보장은 별도 프로젝트 누적 사용량에 달려 있다.

## 화면 구현

기존 `forecast/ui.js`의 시간별/3시간 계산은 유지하고 선택/배치 연결만 추가했다. 새 `forecast/daily.js`가 일별 원값 표와 모바일 탭을 담당한다. 오늘 포함7일의 일자/요일·오전/오후·날씨 아이콘·최저/최고·강수확률을 표시한다. 토요일/일요일 구분,0℃/0% 보존,결측은 `-`,24시간 중기값은 하루1칸으로 표시한다. 날씨 문구는 아이콘의 도움말과 접근성 텍스트로 제공한다.

PC는1시간/3시간/일별 독립3창이며 일별은3시간 아래 오른쪽에 둔다. 기존 두 창의 기본 배율은 유지하고 새 일별 창은 작은 표로 시작한다. 모두 가로 스크롤 가능하고 일별도 이동·크기 조절·개별 닫기가 가능하다. 낮은 화면에서는 창 내부에서 세로로 스크롤할 수 있다. 출처/발표 상세는 표 아래 펼침 항목과 각 값의 도움말로 확인한다.

휴대폰은 예보창1개에1시간/3시간/일별3탭과 닫기1개를 제공한다. 선택 탭만 표시하고,화살표/Home/End 키와 탭 접근성 표지를 지원한다. 모바일은 일별 탭을 열 때 한 격자를 조회한다. PC는 선택 시 조회하고 보이는 일별만10분마다 갱신(실패3분),숨긴 화면/닫힌 창에는 반복 호출하지 않는다. 이전 격자의 늦은 응답을 무시하며 표 갱신 중 가로 스크롤과 선택 탭을 유지한다. 화면은 KMA를 직접 호출하지 않는다.

새 계산/표 시험7/7,브라우저의PC3창·휴대폰3탭·실패 후 재시도/화면 크기 전환·늦은 응답/같은 칸 재선택을 단독 검증했다. PC와 모바일 화면을 실제 렌더링해 확인했다. 새 응답지연 시험은 처음 Playwright 대기식이 함수를 호출해버려 실패했으며 `typeof` 조건으로 고쳐 단독 통과했다. 변경 전/중단된 전체시험은 통과로 집계하지 않는다. 최종 전체시험 결과와 수집기 배포/실수집 검증은 완료 후 기록한다.

## 창 배치 간소화 (2026-11-07 후속 사용자 요청)

모바일 창은 화면 중앙에 두고,중복된 패널 제목을 숨겼다. 탭 옆에 선택 지명과 지사만 표시하며 격자 번호는 넣지 않는다. 반투명 배경으로 화면을 막지 않으므로 창을 닫지 않고 다른 격자 줄이나 지도 칸을 선택할 수 있다.

PC는 제목을 표 왼쪽 세로 영역으로 옮겨 위쪽 제목 줄을 없앴다. 새 기본 배율/위치(`compact-v2`)로 시작하며 예전 큰 창 설정을 그대로 적용하지 않는다. 글자·칸 여백을 줄이고,열린 세 창의 높이를 지도와 하단 범례 위에 들어오도록 함께 맞춘다. 창 자체의 세로 스크롤은 없고 표의 가로 스크롤만 허용한다. 이동·크기 조절은 유지한다. 창 위의 세로 휠을 가로 이동으로 바꾸며 Ctrl/Meta 확대 제스처는 가로 이동으로 가로채지 않는다.

24시간 합계/자동선택 이유와 일별 출처 펼침 설명은 사용자 요청대로 창에서 제거했다. 기온·날씨의 발표/출처는 각 값의 도움말에 보존한다. 예보값·수집·SQL·API 호출량은 바뀌지 않았다. 자동 격자 선택의 순서도 유지한다.
