# 열린 예보창의 칸별 자동 갱신

2026-11-05 사용자 요청: 하루치가 모일 때까지 기다리지 말고 들어온 3시간 칸부터 표시한다.

## 확인한 원인과 변경 범위

서버69는 이미 `done_at`까지 기다리지 않는다. 각 예보 시각의 TMP/SNO/PCP/POP/PTY가 준비된 최신 발표를 선택해 읽고, 3시간 칸을 집계한다. 준비 중에는 기존 발표 자료를 대체로 사용할 수 있다. 다만 화면은 격자를 고른 직후 한 번만 이후 예보를 조회하고 같은 창을 계속 열어 두면 다시 읽지 않았다.

`forecast/ui.js`의 선택 격자 재조회를 추가했다. 수집 중(`collecting=true`)·오류 재시도는3분, 수집 완료 후에는10분 간격이다. 다음 칸이 준비되면 하루치 전체 완료와 관계없이 다음 조회에 반영한다. 상단24시간도 같은 응답을 사용한다. 브라우저가 보이지 않거나 예보 탭을 떠났거나 두 창을 모두 닫았으면 반복 조회하지 않는다. 브라우저로 돌아왔을 때 마지막 성공 조회에서1분 이상 지났으면 바로 확인한다. 다른 격자를 선택하면 이전 격자의 늦은 응답은 버린다.

응답이 그대로면 표를 다시 그리지 않는다. 바뀐 응답에서는 가로 스크롤·창 위치와 크기·닫은 창 상태를 유지한다. 일시적인 갱신 실패로 기존 표를 비우지 않으며 다음3분 주기에 재시도한다. 첫 조회 실패는 기존 오류 안내와 다시 받기를 유지한다.

서버 SQL·기상청 수집 예약·API 호출·기존 정량 경계는 변경하지 않는다. 화면이 보일 때 선택한 한 격자의 Supabase 조회만 늘어난다. 실제 전달량은 사용 시간과 사용자 수에 비례한다. 숨겨진 화면에서 정기적으로 전국 격자를 내려받지 않는다.

## 날짜 범위와 구별

3시간 칸별 수집 완료와 기상청의 정량 제공 끝은 별개다. 정성 코드·결측 구간을 수치 강수/적설로 바꾸지 않으며 기존 화면 필터를 유지한다. 따라서 제공 범위 밖인9일 정량 예보가 오늘21시에 새로 생기는 기능은 아니다. 5일17시 발표에서 정량 끝은9일00시(8일24시), 원자료 끝은10일00시였다.

수집된 부분 칸은 기존69 계약대로 실제 받은 시각 범위를 사용한다. 가상의 빈 시간을0으로 메우거나 하루치 데이터를 기다리지 않는다.

## 검증

- 다음 한 칸이 준비된 응답으로 바뀌면3분 후 한 칸 추가, 상단24시간·가로 스크롤·창 위치/폭 유지.
- 브라우저 숨김·다른 탭·두 창 닫기 시 조회 정지, 다시 보이면 재개.
- 재조회 실패 시 기존 표 유지, 다음 주기에 정상 재시도.
