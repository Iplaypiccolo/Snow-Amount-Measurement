# 예보 격자 한 칸 확대 검토

2026-11-05 `snow-support`의 실제 유효 편입 좌표를 읽기 전용으로 계산했다. **격자 확대는 적용하지 않았다.**

| 범위 | 전국 고유 격자 | 지사별 편입 관계 합계 |
|---|---:|---:|
| 현재 | 924 | 1,059 |
| 상하좌우 한 칸 확대 | 1,975 | 2,734 |
| 대각선을 포함한 둘레 한 칸 확대 | 2,289 | 3,463 |

대각선까지 포함하면 고유 격자는 약 2.48배, 지사 평균 편입은 약 18→59칸으로 3.27배가 된다. 여러 지사가 같은 격자를 공유하므로 두 증가율은 다르다. 기상청 좌표 범위 안에서 중복을 제거한 계산이며, 바다나 기상값이 없는 칸의 적합성까지 검사한 결과는 아니다.

## 기상청 API

현재 수집기는 변수·예보시각마다 전국 37,697칸 응답을 받은 뒤 필요한 좌표를 추린다(`collect-forecast/core.mjs`, `pickCells`). 따라서 평상시 기상청 요청 횟수는 격자 수에 비례해 늘지 않는다. 저장 배열, 캐시, 좌표 목록과 지사별 조회 자료는 늘어난다. 새 격자의 최초 자료를 채우는 방법은 적용할 때 별도로 정해야 한다. 기존 관리 화면의 칸당 호출 예산은 옛 추정이므로 이번 계산에 사용하지 않았다.

## Supabase Egress

현재 지사별 24시간 추이의 JSON 행 크기를 SQL로 계산하면 평균 10,921바이트다. 새 격자의 값 길이가 비슷하다고 가정한 대각선 포함 확대 추정치는 평균 35,709바이트로 약 3.27배다. 한 격자를 선택해서 읽는 3시간 예보 응답은 전체 격자 수만큼 커지는 구조가 아니다.

| 지사 추이 신규 조회 가정 | 현재 월 본문 | 확대 월 본문 | 추가 월 본문 |
|---|---:|---:|---:|
| 하루 1,000회 × 30일 | 약 0.328GB | 약 1.071GB | 약 0.744GB |

이는 **압축 전 JSON 행 크기에 따른 비교 모형이며 실제 과금 Egress 측정값이 아니다.** 메타데이터, 헤더, 압축, 본부 지도, 다른 화면, 로그인, 수집기 통신 등은 포함하지 않았다. 화면에서 클릭해도 캐시를 사용하면 신규 조회가 발생하지 않을 수 있다.

[Supabase 공식 Egress 안내](https://supabase.com/docs/guides/platform/manage-your-usage/egress)에 따르면 Free의 일반 Egress 5GB와 캐시 Egress 5GB는 별도 한도이며, 조직의 여러 프로젝트와 서비스 사용량이 합산된다. DB/RPC 조회에 두 한도를 합쳐 10GB로 계산하면 안 된다. **조직의 실제 월 사용량과 잔여량은 확인하지 못했으므로 무료 한도 안에 든다고 보장할 수 없다.** 현재 DB 전체 크기는 약 98MB였으나, 관련 없는 자료까지 격자 증가율로 곱해서 저장량을 추정하는 것도 부정확하다.

## 예보 의미와 권장 방향

기본 편입 도구는 고속도로를 1km 간격으로 따라가며 해당 5km 격자를 고른다. 도로 주변 전체를 채우는 방식이 아니어서 성겨 보일 수 있다. 이 설명만으로 실제 도로 구간 누락이 없다고 단정할 수는 없다.

주변 한 칸을 더 편입하는 것은 예보 해상도를 높이는 변경이 아니다. 도로 밖 산지 등의 값도 기관별 최대 적설·강수와 최저 기온에 반영하므로 기관 예보가 달라질 수 있다. 전국 일괄 확대보다 **누락·경계·산악 구간을 먼저 선정해 확대**하고 실제 Egress와 예보 변화를 확인하는 방향을 권한다. 확대 적용은 별도 검토 후 진행한다.
