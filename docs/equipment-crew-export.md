# 기준일자별 인원 코드와 기계화부 엑셀

2026-11-05 사용자 요청. 기존 기관별 장비 표와 저장 흐름을 확장하며 별도의 인원 명부를 공개 저장소에 넣지 않는다.

## 사용 흐름

- 지원 여부와 지원일 사이의 운전원 열은 차량당 두 줄이다. 선택창의 운전원(a~z)·정비원(가~하) 체크박스에서 두 탭 합계 최대 두 명을 고른다. 혼합 선택과 선택 해제가 가능하다.
- 적용은 화면의 변경분에 반영한다. 기존 확정 버튼으로 서버에 저장하고, 되돌리기는 저장된 코드로 복원한다. 장비 수정 권한은 기존과 같다.
- 새 기준일자를 만들 때 직전 기준일자의 코드를 복사한다. 복사 후에는 기준일자별로 독립적으로 변경한다. 기존 지원 여부 초기화·미래 경로 승계 규칙은 유지한다.
- 확정 옆 저장하기는 XLSX 다운로드다. 미확정 장비·경로 변경이 있으면 먼저 확정하도록 안내한다. 기존 저장 막대가 보이는 장비 편집 계정에서 사용한다.
- 새 인원 열을 상단 현황 표의 폭 계산에도 포함한다. 컴퓨터 기관별 장비의 지원일 칸은 11.7em에서 10.8em로 조금 좁히고 지사 선택 입력의 최소 폭을 확보해 기존 글자 크기와 6일 표시를 유지한다. 다른 표의 기본 칸 폭은 유지한다. 휴대전화 행 높이는 인원 두 줄을 수용한다.

## 다운로드 범위와 붙여넣기

사용자 답변: **해당 기준일자의 제일 첫 지원일 다운로드**. 현재 지원일 표시 창을 옮겨도 `support_rounds.start_date`를 사용한다. 파일명에 날짜가 들어간다.

현재 기관 필터에 포함된 기계화부 장비 중 지원 여부가 O이고 그 첫날 지원기관이 실제 배정된 차량만 내려받는다. 지역본부·강원본부 지원장비는 포함하지 않는다. 같은 날 경로가 여러 곳이면 지원기관 한 칸에 화살표로 연결하며 차량 행을 중복하지 않는다. 도공번호가 없는 대상은 확정 후 번호를 넣도록 안내한다.

파일의 붙여넣기 시트는 첨부 예시와 같은 A:F 6열이다. 머리글 두 줄 다음 A3부터 **기관 / 장비 / 도공번호 / 지원기관 / 운전원1 / 운전원2** 순으로 복사해 원본 서식의 붙여넣기 시트 A3에 값으로 붙여넣는다. 기존에 붙인 자료가 더 길었다면 기존 A3:F 자료를 먼저 비워야 남은 행이 집계되지 않는다. 도공번호는 앞자리 0을 보존하는 텍스트다. 지원일은 별도 열을 추가하지 않는다.

원본 통합문서의 현황·인원 명부·수식은 수정하지 않는다. 실제 성명과 연락처를 사이트나 저장소로 가져오지 않으며 서버에는 코드만 저장한다. 내려받기는 브라우저에서 기존 ZIP 도구로 XLSX를 구성하므로 새 외부 라이브러리·파일 서버 저장·정기 작업이 없다.

## 서버 변경 72

`round_vehicle_status.crew text[] NOT NULL DEFAULT '{}'`와 허용 코드·중복 금지·최대 2개 제약을 추가한다. 기존 `save_fleet`의 p_status에 crew를 추가해 같은 확정에서 저장한다. 구버전 클라이언트가 crew를 보내지 않으면 저장된 인원을 지우지 않는다. `create_round`는 기존 차량 선정과 상태 승계 규칙을 유지하면서 직전 인원을 복사한다. 함수 인자·권한·RLS 정책은 유지한다.

적용 전 기존 함수 본문 해시를 검사해 다른 변경이 있으면 전체를 취소한다. 기존 지원·경로·확정 자료는 갱신하지 않는다. SQL 전체를 사용자에게 먼저 제시했다. 적용 및 배포 결과는 아래 검증 기록과 handoff에 남긴다.

## 검증

- 인원 선택·기준일자별 복사와 독립성·첫날 다운로드·읽기 전용 권한 화면 4건, 순수 계산/XLSX 7건 통과.
- 실제 함수 본문과 RLS를 사용하는 로컬 PostgreSQL 호환 환경 12건 통과: 혼합 두 명 저장, 누락 payload 보존, 잘못된 코드 거절, 자기 기관 권한, 타 기관/읽기 전용 거절, 인원만 변경, 복사/개별 수정/해제, 확정 자료 불변.
- 컴퓨터 1440px·휴대전화 390px 선택창 확인. 휴대전화 선택창 가로 넘침 없음.
- 시험용 다운로드 ZIP/CRC·6열·코드·머리글 검증과 XLSX 가져오기/렌더 확인. 실명 명부는 시험 자료에 넣지 않았다.
- 전체27개 시험 묶음449/449(493.5초) 통과. 실서버72 `round_vehicle_crew_72` / `20261105083747` 적용. 지원 상태24행·경로7행·지사 요청63행의 기존 열 지문은 전후 동일하고 crew는 모두 빈 배열로 시작한다. 함수 실행 권한과 RLS 유지, 새로운 보안 검사 경고 없음.
- 실서버 운영 차량의 인원을 시험 목적으로 바꾸지 않았다. 실제 계정의 저장·다운로드는 운영 데이터를 바꾸지 않는 로컬 화면/SQL 검증과 구분한다.
- REST에서도 crew 열 인식을 확인했다(없는 열은42703, 실제 crew 조회는 비로그인 권한 차단42501). 비로그인에게 자료를 공개하지 않는다. 검사 중 인트로 시간 초과는 로그인 묶음 별도24/24 재실행과 최종 전체449/449로 확인했고 제품 로그인 코드는 바꾸지 않았다. 전체 시험은 긴 장비 묶음을 먼저 시작하고 인트로를 초기 계산 부하 뒤에 시작하도록 순서만 조정했다.
